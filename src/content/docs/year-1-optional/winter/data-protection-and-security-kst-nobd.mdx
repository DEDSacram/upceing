## Week 1: Sensitive Data & Information Systems

This week introduces the concept of sensitive data, its legal protections, and the distinction between open and closed information systems.

### Key Concepts

- **Sensitive Data** – Personal data, health records, financial information, trade secrets, and any data whose disclosure could cause harm.
- **Open vs. Closed Information Systems** – Open systems allow public access (e.g., public websites); closed systems restrict access to authorized users (e.g., internal corporate networks).
- **Legal Frameworks** – The GDPR, national laws, and industry standards (e.g., PCI DSS) mandate protection for sensitive data.

### Identifying Sensitive Data

The classification of data sensitivity depends on:
- **Confidentiality** – Should the data be secret?
- **Integrity** – Is accuracy critical?
- **Availability** – Is uptime essential?

```python
# Example: Data classification helper
def classify_data(data_type, context):
    sensitivity_levels = {
        'personal': 'HIGH',
        'financial': 'HIGH',
        'health': 'VERY HIGH',
        'public': 'LOW',
        'internal': 'MEDIUM'
    }
    return sensitivity_levels.get(data_type, 'UNKNOWN')
```

## Week 2: Encoding, Encryption & History of Cryptography

This week covers the fundamentals: encoding vs. encryption, the history of cryptographic techniques, and implementation of simple classical ciphers.

### Key Concepts

- **Encoding** – Converting data from one form to another (e.g., Base64, ASCII). No security is provided.
- **Encryption** – Converting plaintext to ciphertext using a key. Provides confidentiality.
- **History** – From the Caesar cipher (ancient Rome) through the Enigma machine (WWII) to modern public‑key cryptography.

### Simple Ciphers

**Caesar Cipher** – Each letter is shifted by a fixed number of positions.

```python
def caesar(text, shift, decrypt=False):
    result = []
    shift = -shift if decrypt else shift
    for char in text:
        if char.isalpha():
            base = ord('A') if char.isupper() else ord('a')
            result.append(chr((ord(char) - base + shift) % 26 + base))
        else:
            result.append(char)
    return ''.join(result)

# Example: Caesar cipher with shift 3
print(caesar("HELLO", 3))  # KHOOR
```

**Vigenère Cipher** – Uses a keyword to create multiple Caesar shifts.

## Week 3: Relations & Mappings

Mathematical relations and mappings form the foundation of cryptographic functions. This week covers equivalence relations, functions, and modular arithmetic.

### Key Concepts

- **Relation** – A set of ordered pairs. Examples: "less than", "congruent modulo n".
- **Equivalence Relation** – Reflexive, symmetric, transitive. Creates equivalence classes.
- **Mapping (Function)** – A relation where each input has exactly one output.
- **Modular Arithmetic** – Arithmetic on residue classes modulo n. The basis for many cryptographic algorithms.

### Modular Arithmetic in Python

```python
# Modular arithmetic operations
def mod_add(a, b, n): return (a + b) % n
def mod_mul(a, b, n): return (a * b) % n
def mod_pow(base, exp, n): return pow(base, exp, n)  # Built‑in efficient exponentiation

# Example: Extended Euclidean algorithm for modular inverse
def mod_inverse(a, n):
    # Returns x such that a*x ≡ 1 (mod n), or None if not invertible
    t, new_t = 0, 1
    r, new_r = n, a
    while new_r != 0:
        q = r // new_r
        t, new_t = new_t, t - q * new_t
        r, new_r = new_r, r - q * new_r
    if r > 1: return None  # Not invertible
    if t < 0: t += n
    return t
```

## Week 4: Groups

Groups are fundamental algebraic structures used in cryptography. This week covers group definitions, properties, and examples such as cyclic groups and the multiplicative group of integers modulo n.

### Key Concepts

- **Group (G, *)** – A set G with operation * satisfying: closure, associativity, identity element, and inverse element.
- **Abelian Group** – Commutative group (a * b = b * a).
- **Cyclic Group** – Generated by a single element g; every element is g^k for some integer k.
- **Order** – The number of elements in the group (for finite groups).
- **Subgroup** – A subset that is itself a group.

### Example: Multiplicative Group Modulo n

```python
# Find all elements of the multiplicative group modulo n
def multiplicative_group(n):
    elements = [a for a in range(1, n) if math.gcd(a, n) == 1]
    return elements

# Check if a number is a generator (primitive root)
def is_generator(g, n):
    elements = multiplicative_group(n)
    powers = set()
    for i in range(1, len(elements) + 1):
        powers.add(pow(g, i, n))
    return len(powers) == len(elements)
```

## Week 5: Fields

Fields are algebraic structures where addition, subtraction, multiplication, and division (except by zero) are defined. Finite fields (Galois fields) are crucial for coding theory and cryptography.

### Key Concepts

- **Field (F, +, *)** – A set with two operations: addition (forming an abelian group) and multiplication (forming an abelian group except for zero). Distributivity holds.
- **Finite Field GF(p)** – The field of integers modulo a prime p.
- **Finite Field GF(2^n)** – Field of polynomials over GF(2) modulo an irreducible polynomial. Used in AES and other ciphers.

### Example: GF(2^3) with irreducible polynomial x^3 + x + 1

```python
# Represent elements as integers (bits), addition is XOR
# Multiplication modulo the irreducible polynomial
def gf_mul(a, b, mod=0b1011):  # mod = x^3 + x + 1
    result = 0
    while b:
        if b & 1:
            result ^= a
        b >>= 1
        a <<= 1
        if a & 0b1000:  # degree >= 3
            a ^= mod
    return result & 0b111
```

## Week 6: Linear & Cyclic Codes

Error‑detecting and error‑correcting codes are essential for reliable data transmission. This week covers linear codes, Hamming codes, and cyclic codes.

### Key Concepts

- **Linear Code** – A subspace of GF(q)^n with dimension k. Represented by a generator matrix G (k×n) and parity‑check matrix H ((n−k)×n).
- **Hamming Code** – A perfect 1‑error‑correcting code with parameters (2^m−1, 2^m−1−m).
- **Cyclic Code** – A linear code where every cyclic shift of a codeword is also a codeword. Represented by a generator polynomial.
- **Minimum Distance** – The minimum Hamming distance between any two codewords. Determines error‑correcting capability.

### Example: Hamming Code (7,4) Encoding

```python
# Generator matrix for (7,4) Hamming code
G = [
    [1, 0, 0, 0, 1, 1, 1],
    [0, 1, 0, 0, 1, 1, 0],
    [0, 0, 1, 0, 1, 0, 1],
    [0, 0, 0, 1, 0, 1, 1]
]

def hamming_encode(data):
    # data: list of 4 bits
    return [sum(G[i][j] * data[i] for i in range(4)) % 2 for j in range(7)]
```

## Week 7: Lattices & Boolean Algebras

Lattices and Boolean algebras provide the mathematical foundation for access control models and logic circuits. This week covers these structures and their security applications.

### Key Concepts

- **Partially Ordered Set (Poset)** – A set with a reflexive, antisymmetric, transitive order relation.
- **Lattice** – A poset where every pair of elements has a unique least upper bound (join) and greatest lower bound (meet).
- **Boolean Algebra** – A complemented distributive lattice. Used in access control (Bell–LaPadula model).
- **Security Lattices** – Used to model security levels (e.g., TOP SECRET > SECRET > CONFIDENTIAL > UNCLASSIFIED).

### Example: Bell–LaPadula Security Model

```python
class SecurityLevel:
    def __init__(self, classification, categories=None):
        self.classification = classification  # e.g., 'TS', 'S', 'C', 'U'
        self.categories = categories or set()  # e.g., {'NUCLEAR', 'FINANCE'}
    
    def dominates(self, other):
        # Simple dominance: classification >= other and categories superset
        order = {'TS': 4, 'S': 3, 'C': 2, 'U': 1}
        return (order[self.classification] >= order[other.classification] and
                self.categories.issuperset(other.categories))
```

## Week 8: Prime Factorization & Primality Testing

Prime numbers are the cornerstone of modern cryptography. This week covers factorization, primality testing, and prime generation.

### Key Concepts

- **Fundamental Theorem of Arithmetic** – Every integer > 1 can be uniquely factored into primes.
- **Trial Division** – Simple but inefficient for large numbers.
- **Miller–Rabin Primality Test** – A probabilistic test that is fast and widely used.
- **Sieve of Eratosthenes** – Generates all primes up to a limit.
- **Prime Generation** – Generating large primes for RSA involves selecting random numbers and testing them.

### Miller–Rabin Implementation

```python
import random

def miller_rabin(n, k=5):
    if n < 2: return False
    if n in (2, 3): return True
    if n % 2 == 0: return False
    
    # Write n-1 = 2^r * d
    r, d = 0, n - 1
    while d % 2 == 0:
        r += 1
        d //= 2
    
    # Witness loop
    for _ in range(k):
        a = random.randint(2, n - 2)
        x = pow(a, d, n)
        if x == 1 or x == n - 1:
            continue
        for _ in range(r - 1):
            x = pow(x, 2, n)
            if x == n - 1:
                break
        else:
            return False
    return True
```

## Week 9: Asymmetric Ciphers

Asymmetric (public‑key) cryptography revolutionized security. This week covers the RSA algorithm and the Diffie–Hellman key exchange.

### Key Concepts

- **RSA** – Based on the difficulty of factoring large numbers. Key generation: choose two large primes p and q, compute n = p*q, φ(n) = (p−1)(q−1), choose e coprime to φ(n), compute d = e^(−1) mod φ(n).
- **Diffie–Hellman** – Allows two parties to agree on a shared secret over an insecure channel using discrete logarithms.
- **Security** – Based on the discrete logarithm problem (DLP) and integer factorization problem (IFP).

### RSA Implementation

```python
def rsa_keygen(bits):
    p = generate_prime(bits // 2)
    q = generate_prime(bits // 2)
    n = p * q
    phi = (p - 1) * (q - 1)
    e = 65537  # Common public exponent
    d = mod_inverse(e, phi)
    return (e, n), (d, n)  # public, private

def rsa_encrypt(m, public_key):
    e, n = public_key
    return pow(m, e, n)

def rsa_decrypt(c, private_key):
    d, n = private_key
    return pow(c, d, n)
```

## Week 10: Key Management & Cryptocurrencies

Key management is one of the hardest parts of cryptography. This week covers PKI, certificate management, and the cryptographic principles behind cryptocurrencies.

### Key Concepts

- **Key Management** – Generation, distribution, storage, renewal, and revocation of keys.
- **PKI (Public Key Infrastructure)** – System of CAs (Certificate Authorities), certificates (X.509), and CRLs (Certificate Revocation Lists).
- **Blockchain** – A tamper‑evident ledger built on cryptographic hashing and signatures.
- **Cryptocurrencies** – Bitcoin uses ECDSA for signatures, SHA‑256 for hashing, and a proof‑of‑work consensus.

### Simulating Blockchain Basics

```python
import hashlib
import json
import time

class Block:
    def __init__(self, index, transactions, previous_hash):
        self.index = index
        self.timestamp = time.time()
        self.transactions = transactions
        self.previous_hash = previous_hash
        self.nonce = 0
        self.hash = self.compute_hash()
    
    def compute_hash(self):
        block_string = json.dumps({
            'index': self.index,
            'timestamp': self.timestamp,
            'transactions': self.transactions,
            'previous_hash': self.previous_hash,
            'nonce': self.nonce
        }, sort_keys=True)
        return hashlib.sha256(block_string.encode()).hexdigest()
    
    def mine_block(self, difficulty):
        target = '0' * difficulty
        while self.hash[:difficulty] != target:
            self.nonce += 1
            self.hash = self.compute_hash()
        print(f'Block mined: {self.hash}')
```

## Week 11: Security Issues in Resource Sharing & Virtualization

Virtualization introduces unique security challenges. This week covers threats like VM escape, side‑channel attacks, and resource isolation failures.

### Key Concepts

- **Virtualization Security** – Attack surface increases with hypervisors, VMMs, and shared resources.
- **VM Escape** – An attacker breaks out of a VM and gains access to the host or other VMs.
- **Side‑Channel Attacks** – Exploiting resource contention (cache, memory bus, network) to leak information.
- **Container Security** – Containers share the host kernel, so isolation is weaker than VMs.
- **Resource Sharing** – CPU caches, memory, and I/O devices can be exploited.

### Example: Cache‑Based Timing Attack

```python
import time
```

## Week 12: Data Center Solutions

This week covers physical and logical security in data centers, including redundancy, disaster recovery, and access control.

### Key Concepts

- **Data Center Security** – Physical security (fences, biometrics, cameras) and logical security (firewalls, SIEM, access logs).
- **Redundancy** – N+1, 2N, and geographic redundancy to ensure high availability.
- **Disaster Recovery** – RTO (Recovery Time Objective) and RPO (Recovery Point Objective).
- **Security Zones** – DMZ, internal network, and management network separation.

### Designing a Secure Data Center

```python
class DataCenter:
    def __init__(self, name, location):
        self.name = name
        self.location = location
        self.security_zones = {
            'DMZ': {'level': 'LOW', 'services': ['web', 'email']},
            'INTERNAL': {'level': 'MEDIUM', 'services': ['app', 'db']},
            'MANAGEMENT': {'level': 'HIGH', 'services': ['admin', 'monitoring']}
        }
        self.access_control = {}
    
    def grant_access(self, user, zone, time_window):
        self.access_control[user] = {'zone': zone, 'time': time_window}
```

## Code Review Guide

When reviewing security code, focus on:

### Cryptographic Practices
- **Key Management** – Are keys stored securely? Is proper key derivation used?
- **Randomness** – Is a cryptographically secure PRNG used (e.g., `secrets` or `os.urandom`)?
- **Padding** – Are proper padding schemes used (e.g., OAEP for RSA, PKCS#7 for AES)?
- **Protocols** – Are secure versions of protocols used (TLS 1.3, not SSLv3)?

### Access Control
- Is least privilege principle applied?
- Are roles and permissions properly defined?
- Is there proper input validation to prevent injection attacks?

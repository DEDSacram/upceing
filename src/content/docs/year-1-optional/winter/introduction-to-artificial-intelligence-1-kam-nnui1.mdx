## Week 2: Graphs, Transition Systems & Planning

Graph theory forms the foundation for state‑space search. This week we formalize problems as transition systems and introduce planning as searching for a path from an initial state to a goal state.

### Key Concepts

- **Graph** – A set of nodes (states) and edges (transitions) that may be directed or undirected, weighted or unweighted.
- **Transition System** – A formal model of a problem: `(S, A, T, I, G)` where:
  - `S` – set of states
  - `A` – set of actions
  - `T` – transition function `S × A → S`
  - `I` – initial state
  - `G` – set of goal states
- **Planning** – Finding a sequence of actions that transforms the initial state into a goal state.

## Week 3: Uninformed Search – BFS & DFS

Uninformed (blind) search algorithms explore the state space without using domain‑specific knowledge. We cover breadth‑first search (BFS) and depth‑first search (DFS).

### Key Concepts

- **BFS** – Explores all nodes at the current depth before moving to the next depth. Guarantees the shortest path in terms of number of steps (unweighted). Uses a queue (FIFO).
- **DFS** – Explores as far as possible along a branch before backtracking. Uses a stack (LIFO). Not guaranteed to find the shortest path; may get stuck in infinite loops if cycles are not handled.
- **Complexity** – BFS: O(b^d) time, O(b^d) space; DFS: O(b^m) time, O(b*m) space (where b = branching factor, d = depth of shallowest goal, m = maximum depth).

### Implementation

```python
from collections import deque

def bfs(graph, start, goal):
    visited = set()
    queue = deque([(start, [start])])
    while queue:
        node, path = queue.popleft()
        if node == goal:
            return path
        if node not in visited:
            visited.add(node)
            for neighbor in graph.get(node, []):
                if neighbor not in visited:
                    queue.append((neighbor, path + [neighbor]))
    return None

def dfs_iterative(graph, start, goal):
    visited = set()
    stack = [(start, [start])]
    while stack:
        node, path = stack.pop()
        if node == goal:
            return path
        if node not in visited:
            visited.add(node)
            for neighbor in graph.get(node, []):
                if neighbor not in visited:
                    stack.append((neighbor, path + [neighbor]))
    return None
```

## Week 4: Advanced Uninformed Search

We extend the basic search algorithms to handle depth limits, iterative deepening, bidirectional search, and uniform‑cost search for weighted graphs.

### Key Concepts

- **Depth‑Limited DFS** – DFS with a maximum depth cutoff to avoid infinite loops.
- **Iterative Deepening DFS (IDDFS)** – Repeatedly runs depth‑limited DFS with increasing limits. Combines the space efficiency of DFS with the completeness of BFS (for finite branching factor).
- **Bidirectional Search** – Run two simultaneous searches (forward from start, backward from goal) and stop when they meet. Significantly reduces time complexity to O(b^(d/2)).
- **Uniform‑Cost Search (UCS)** – Generalization of BFS for weighted graphs. Uses a priority queue (min‑heap) ordered by path cost. Equivalent to Dijkstra's algorithm.

### Implementation of UCS

```python
import heapq

def ucs(graph, start, goal):
    # graph: dict node -> {neighbor: cost}
    frontier = [(0, start, [start])]  # (cost, node, path)
    visited = set()
    while frontier:
        cost, node, path = heapq.heappop(frontier)
        if node == goal:
            return path, cost
        if node not in visited:
            visited.add(node)
            for neighbor, edge_cost in graph.get(node, {}).items():
                if neighbor not in visited:
                    heapq.heappush(frontier, (cost + edge_cost, neighbor, path + [neighbor]))
    return None, float('inf')
```

## Week 5: Informed Search & Heuristics

Informed (heuristic) search uses domain‑specific knowledge to guide the search, improving efficiency. The most prominent algorithm is A*.

### Key Concepts

- **Heuristic Function** `h(n)` – Estimates the cost from node n to the goal. Must be admissible (never overestimates) and consistent (monotonic) for A* to be optimal.
- **A* Algorithm** – Combines uniform‑cost search (g(n) = cost from start) with heuristic (h(n)): f(n) = g(n) + h(n). Uses a priority queue ordered by f(n).
- **Greedy Best‑First Search** – Uses only h(n); not optimal but often faster.
- **Designing Heuristics** – Common methods: relax the problem (e.g., Manhattan distance for 8‑puzzle), subproblem, pattern databases.

### A* Implementation

```python
def a_star(graph, start, goal, heuristic):
    frontier = [(heuristic(start), 0, start, [start])]  # (f, g, node, path)
    visited = {}
    while frontier:
        f, g, node, path = heapq.heappop(frontier)
        if node == goal:
            return path, g
        if node not in visited or g < visited[node]:
            visited[node] = g
            for neighbor, step_cost in graph.get(node, {}).items():
                new_g = g + step_cost
                new_f = new_g + heuristic(neighbor)
                heapq.heappush(frontier, (new_f, new_g, neighbor, path + [neighbor]))
    return None, float('inf')
```

## Week 6: Game Theory – Minimax & Alpha‑Beta

This week introduces adversarial search for two‑player games. We implement the Minimax algorithm and its optimization, Alpha‑Beta pruning.

### Key Concepts

- **Game Tree** – Nodes represent game states; edges are moves. The root is the initial state.
- **Minimax** – For a zero‑sum game, the player (MAX) tries to maximize the score, while the opponent (MIN) minimizes it. The algorithm recursively computes the value of each state: MAX nodes take the maximum over children, MIN nodes take the minimum.
- **Alpha‑Beta Pruning** – Prunes branches that cannot influence the final decision. Maintains two bounds: α (best value for MAX) and β (best value for MIN). If α ≥ β, prune.

### Implementation (Tic‑Tac‑Toe)

```python
def minimax(board, depth, is_maximizing):
    # Returns (best_score, best_move)
    if game_over(board) or depth == 0:
        return evaluate(board), None
    if is_maximizing:
        best_score = -float('inf')
        best_move = None
        for move in get_legal_moves(board):
            new_board = make_move(board, move, 'X')
            score, _ = minimax(new_board, depth-1, False)
            if score > best_score:
                best_score = score
                best_move = move
        return best_score, best_move
    else:
        best_score = float('inf')
        best_move = None
        for move in get_legal_moves(board):
            new_board = make_move(board, move, 'O')
            score, _ = minimax(new_board, depth-1, True)
            if score < best_score:
                best_score = score
                best_move = move
        return best_score, best_move
```

## Week 7: Introduction to Fuzzy Sets

Fuzzy sets extend classical (crisp) sets by allowing partial membership, represented by a membership degree between 0 and 1. This enables handling of imprecise concepts.

### Key Concepts

- **Membership Function** – Assigns a membership degree μ_A(x) to each element x in the universe of discourse.
- **Basic Operations** – Union (max), Intersection (min), Complement (1 - μ).
- **Support, Core, Height, Normality** – Support: elements with μ > 0; Core: μ = 1; Height: max μ; Normal: height = 1.

### Python Implementation

```python
# Represent fuzzy set as a dict: element -> membership degree
fuzzy_A = {'a': 0.2, 'b': 0.8, 'c': 1.0}
fuzzy_B = {'b': 0.5, 'c': 0.3, 'd': 0.9}

def fuzzy_union(A, B):
    union = {}
    for key in set(A.keys()) | set(B.keys()):
        union[key] = max(A.get(key, 0), B.get(key, 0))
    return union

def fuzzy_intersection(A, B):
    inter = {}
    for key in set(A.keys()) & set(B.keys()):
        inter[key] = min(A.get(key, 0), B.get(key, 0))
    return inter
```

## Week 8: Fuzzy Relations & Numbers

We extend fuzzy set concepts to relations and numbers, and introduce the extension principle for mapping crisp functions to fuzzy domains.

### Key Concepts

- **Fuzzy Relation** – A fuzzy set on the Cartesian product of two universes; membership degree indicates the strength of association.
- **Composition** – Max‑min composition: R ∘ S (x,z) = max_y min(R(x,y), S(y,z)).
- **Fuzzy Numbers** – A fuzzy set on the real line that is normal, convex, and has a bounded support (e.g., triangular, trapezoidal).
- **Extension Principle** – Allows extending a crisp function f: X → Y to fuzzy sets: `f(A)(y) = sup_{x: f(x)=y} μ_A(x)`.

### Python Example: Triangular Fuzzy Number

```python
def triangular_membership(x, a, b, c):
    # a < b < c, peak at b
    if x <= a or x >= c:
        return 0.0
    elif a < x <= b:
        return (x - a) / (b - a)
    else:  # b < x < c
        return (c - x) / (c - b)

# Example: fuzzy number "around 5" with (3,5,7)
print(triangular_membership(4, 3, 5, 7))  # 0.5
```

## Week 9: Linguistic Variables & Approximate Reasoning

Linguistic variables allow the use of natural language terms (e.g., "temperature is high") in fuzzy systems. Approximate reasoning uses fuzzy rules to infer conclusions from imprecise premises.

### Key Concepts

- **Linguistic Variable** – A variable whose values are linguistic terms (fuzzy sets). For example, "temperature" can be &lcub;cold, warm, hot&rcub;.
- **Fuzzy Rules** – If‑then rules with fuzzy antecedents and consequents (e.g., "If temperature is hot and humidity is high, then fan_speed is fast").
- **Fuzzy Inference** – Steps: fuzzification (mapping crisp inputs to membership degrees), rule evaluation (combining antecedents with AND/OR using min/max), aggregation (combining rule outputs), defuzzification (e.g., centroid method).

### Mamdani Inference Example

```python
# Simple rule: If x is A and y is B then z is C
# Use min for AND, max for aggregation
def evaluate_rule(x_val, y_val, A, B, C):
    mu_A = A(x_val)
    mu_B = B(y_val)
    firing_strength = min(mu_A, mu_B)
    # Implication: truncate C
    def implied_C(z):
        return min(firing_strength, C(z))
    return implied_C
```

## Week 10: Fuzzy Logic Systems and Their Applications

We explore the architecture of fuzzy logic systems (FLS) and their real‑world applications, from control systems to decision support.

### Key Concepts

- **Components of FLS** – Fuzzification, Rule Base, Inference Engine, Defuzzification.
- **Defuzzification Methods** – Centroid (center of gravity), bisector, mean of maxima.
- **Types of FLS** – Mamdani (often used for control) and Takagi‑Sugeno (consequents are functions, used for modeling).
- **Applications** – Industrial control (cement kiln, subway trains), consumer electronics (auto‑focus cameras), financial forecasting.

### Example: Centroid Defuzzification

```python
def centroid(output_set, universe):
    numerator = sum(x * output_set(x) for x in universe)
    denominator = sum(output_set(x) for x in universe)
    return numerator / denominator if denominator != 0 else 0
```

## Week 11: Stochastic Optimization Methods

This week covers randomized search techniques that are useful for complex optimization problems where deterministic methods fail.

### Key Concepts

- **Monte Carlo** – Random sampling to estimate properties (e.g., approximate pi, compute integrals).
- **Hill Climbing** – Iterative improvement by moving to a better neighbor. Susceptible to local optima.
- **Tabu Search** – Uses a memory (tabu list) to avoid revisiting recent solutions, encouraging exploration.
- **Simulated Annealing** – Accepts worse solutions with a probability that decreases over time (annealing schedule) to escape local optima.
- **Ant Colony Optimization** – Inspired by ant foraging, uses pheromone trails to build solutions for path‑finding problems (e.g., TSP).

### Simulated Annealing for TSP (pseudo‑code)

```python
def simulated_annealing(initial_solution, cost_func, neighbor_func, schedule):
    current = initial_solution
    current_cost = cost_func(current)
    for t in range(max_iter):
        T = schedule(t)
        if T == 0: break
        candidate = neighbor_func(current)
        candidate_cost = cost_func(candidate)
        delta = candidate_cost - current_cost
        if delta < 0 or random.random() < math.exp(-delta / T):
            current = candidate
            current_cost = candidate_cost
    return current, current_cost
```

## Week 12: Genetic Algorithms & Differential Evolution

Evolutionary algorithms mimic natural selection. Genetic algorithms (GA) and differential evolution (DE) are among the most popular.

### Key Concepts

- **Genetic Algorithm** – Population of chromosomes; selection (roulette, tournament), crossover (one‑point, uniform), mutation (bit‑flip, Gaussian).
- **Fitness Function** – Evaluates the quality of a solution.
- **Elitism** – Preserve the best individuals each generation.
- **Differential Evolution** – For continuous optimization; creates new candidate by adding weighted difference of two population members to a third.

### GA Implementation (binary string for knapsack)

```python
import random

def ga(pop_size, fitness, crossover, mutate, generations):
    pop = [random.choices([0,1], k=chromosome_length) for _ in range(pop_size)]
    for _ in range(generations):
        # fitness
        fitnesses = [fitness(ind) for ind in pop]
        new_pop = []
        # elitism: keep top 2
        sorted_pop = [x for _, x in sorted(zip(fitnesses, pop), reverse=True)]
        new_pop.extend(sorted_pop[:2])
        # fill rest
        while len(new_pop) < pop_size:
            p1 = tournament_selection(pop, fitnesses)
            p2 = tournament_selection(pop, fitnesses)
            child = crossover(p1, p2)
            child = mutate(child)
            new_pop.append(child)
        pop = new_pop
    return max(pop, key=fitness)
```

## Week 13: Hybrid Evolutionary Algorithms

Hybrid algorithms combine evolutionary methods with local search (memetic algorithms) or other techniques to exploit their strengths and mitigate weaknesses.

### Key Concepts

- **Memetic Algorithms** – GA + local search (e.g., hill climbing) applied to each individual after crossover/mutation.
- **Lamarckian vs. Baldwinian** – Lamarckian: update chromosome with improved solution; Baldwinian: keep chromosome but update fitness.
- **Co‑evolutionary Algorithms** – Multiple populations that co‑evolve (e.g., predator‑prey).
- **Grammar‑guided Genetic Programming** – Uses context‑free grammars to constrain solutions.

## Code Review Guide

When reviewing code for AI projects, focus on these aspects:

### Algorithm Correctness
- Does the search algorithm correctly handle cycles and visited states?
- Are heuristics admissible and consistent (if applicable)?
- For fuzzy systems: are membership functions properly defined and rule bases complete?

### Efficiency
- Are data structures appropriate (e.g., priority queue for A*)?
- Are there any redundant computations?
- For evolutionary algorithms: is the population size and number of generations reasonable?

### Readability & Documentation
- Are functions and variables named clearly?
- Are the main steps of the algorithm commented?

### Search Algorithms Summary

| Algorithm | Strategy | Complete? | Optimal? | Time | Space |
| :--- | :--- | :--- | :--- | :--- | :--- |
| BFS | Queue (FIFO) | Yes (finite) | Yes (unweighted) | O(b^d) | O(b^d) |
| DFS | Stack (LIFO) | No (infinite) | No | O(b^m) | O(b*m) |
| IDDFS | DFS with increasing depth | Yes | Yes (unweighted) | O(b^d) | O(b*d) |
| UCS | Priority queue (g) | Yes | Yes (weighted) | O(b^(1+floor(C*/ε))) | O(b^(1+floor(C*/ε))) |
| A* | Priority queue (g+h) | Yes (finite) | Yes (admissible h) | Exponential | Exponential |
| Minimax | Recursive minimax | Yes (finite game) | Yes (perfect play) | O(b^d) | O(b*d) |

### Fuzzy Logic Operations

| Operation | Formula |
| :--- | :--- |
| Union (OR) | μ_A∪B(x) = max(μ_A(x), μ_B(x)) |
| Intersection (AND) | μ_A∩B(x) = min(μ_A(x), μ_B(x)) |
| Complement (NOT) | μ_¬A(x) = 1 - μ_A(x) |
| Implication (Mamdani) | μ_R(x,y) = min(μ_A(x), μ_B(y)) |
| Composition (max‑min) | μ_R∘S(x,z) = max_y min(μ_R(x,y), μ_S(y,z)) |

### Evolutionary Algorithm Parameters

- **Population size** – typically 50–200.
- **Selection** – tournament (k=2–7) or roulette wheel.
- **Crossover rate** – 0.6–0.9.
- **Mutation rate** – 0.001–0.1 (for binary), 0.1–0.5 for real‑valued.
- **Elitism** – keep 1–2 best individuals.

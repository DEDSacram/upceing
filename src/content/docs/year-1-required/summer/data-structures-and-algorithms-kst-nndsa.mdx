## Week 1: String Encoding — Huffman and Lempel-Ziv

Compression removes redundancy: Huffman assigns short codes to frequent symbols (optimal prefix code); LZ methods replace repeats with back-references. Both illustrate greedy correctness and dictionary trade-offs.

### Huffman Essentials

| Step | Action |
|------|--------|
| Count | Frequency table of symbols |
| Build | Repeatedly merge two lowest nodes (min-heap) |
| Code | Left 0 / right 1; prefix-free by construction |
| Bound | Average length within 1 bit of entropy |

### LZ Family

| Variant | Idea |
|---------|------|
| LZ77 | Sliding window `(offset, length, next)` triples |
| LZ78 | Explicit dictionary, `code + char` pairs |
| LZW | Pre-seeded dict (GIF), code-only stream |

```python
import heapq
def huffman(freq):
    heap = [[w, [s, ""]] for s, w in freq.items()]
    heapq.heapify(heap)
    while len(heap) > 1:
        lo = heapq.heappop(heap); hi = heapq.heappop(heap)
        for pair in lo[1:]: pair[1] = "0" + pair[1]
        for pair in hi[1:]: pair[1] = "1" + pair[1]
        heapq.heappush(heap, [lo[0] + hi[0]] + lo[1:] + hi[1:])
    return dict((s, c) for s, c in heap[0][1:])

print(huffman({"a": 45, "b": 13, "c": 12, "d": 16, "e": 9, "f": 5}))
```

## Week 2: String Searching — KMP, Karp-Rabin, Automaton

Naive matching rescans; KMP skips via the prefix function `π`; Karp-Rabin filters via rolling hash; a full string-matching automaton precomputes transitions. All achieve linear or expected-linear time.

### Comparison

| Algorithm | Preprocessing | Search | Idea |
|-----------|---------------|--------|------|
| Naive | — | `O(nm)` | Rescan everything |
| KMP | `O(m)` | `O(n)` | `π` = longest proper prefix-suffix |
| Karp-Rabin | `O(m)` | `O(n+m)` expected | Rolling hash, verify hits |
| Automaton | `O(m·σ)` | `O(n)` | DFA over alphabet |

### KMP Prefix Function

```python
def prefix_function(p: str):
    pi = [0] * len(p)
    for i in range(1, len(p)):
        j = pi[i - 1]
        while j > 0 and p[i] != p[j]:
            j = pi[j - 1]
        if p[i] == p[j]:
            j += 1
        pi[i] = j
    return pi

def kmp_search(text, pat):
    pi = prefix_function(pat)
    j = 0; hits = []
    for i, ch in enumerate(text):
        while j > 0 and ch != pat[j]:
            j = pi[j - 1]
        if ch == pat[j]: j += 1
        if j == len(pat):
            hits.append(i - j + 1); j = pi[j - 1]
    return hits

print(prefix_function("ababaca"))  # [0,0,1,2,3,0,1]
print(kmp_search("ababaababaca", "ababaca"))
```

## Week 3: Prefix Trees — Trie and de la Briandais

Tries share prefixes for fast `O(|key|)` lookup, autocomplete, and sorting. The de la Briandais (left-child / right-sibling) representation stores sparse children without wide arrays — ideal for large alphabets.

### Representations

| Variant | Children storage | Memory |
|---------|------------------|--------|
| Array trie | `σ` pointers/node | Fast, wasteful |
| Map trie | Hash/ordered map | Balanced default |
| de la Briandais | First-child + next-sibling | Compact, pointer chase |

```python
class DLBNode:
    __slots__ = ("ch", "child", "sibling", "value")
    def __init__(self, ch=""):
        self.ch = ch; self.child = None; self.sibling = None; self.value = None

def dlb_insert(root, key, value):
    node = root
    for ch in key:
        prev, cur = None, node.child
        while cur and cur.ch != ch:
            prev, cur = cur, cur.sibling
        if cur is None:
            cur = DLBNode(ch)
            cur.sibling = node.child; node.child = cur
        node = cur
    node.value = value
```

## Week 5: BST Tables — AVL, Treap, Splay

Balanced BSTs keep `O(log n)` height differently: AVL enforces `|balance| ≤ 1` with rotations; treaps combine BST order with heap priorities; splay trees move accessed nodes to root (amortized log, adaptive to locality).

### Rotations and Fixes

| Tree | Invariant | Fix |
|-----|-----------|-----|
| AVL | Height diff ≤ 1 | Single/double rotations |
| Treap | BST + heap on random priority | Rotate up on insert |
| Splay | None explicit | Zig / zig-zig / zig-zag |

```python
class Node:
    __slots__ = ("k", "l", "r", "h")
    def __init__(self, k): self.k = k; self.l = self.r = None; self.h = 1

def height(n): return n.h if n else 0
def rot_right(y):
    x = y.l; y.l = x.r; x.r = y
    y.h = 1 + max(height(y.l), height(y.r))
    x.h = 1 + max(height(x.l), height(x.r))
    return x
```

## Week 6: K-Way Search Trees — 2-3, a-b, B-Tree

Multiway trees reduce height for disk: 2-3 trees (all leaves same depth, 2- or 3-children), general `(a,b)`-trees, and B-trees (node = page, `t` = minimum degree). Splits propagate upward; all leaves stay level.

### Parameters

| Tree | Node occupancy | Height |
|------|---------------|--------|
| 2-3 | 1–2 keys, 2–3 children | `O(log n)` |
| (a,b) | `a-1..b-1` keys | `O(log n)` |
| B-tree `t` | `t-1..2t-1` keys | `O(log_{t} n)` |

```text
B-tree (t=2) insert 10,20,5,6,12,30,7,17 — split full child first:
  [10,20] + insert 5,6 → split → root [10], children [5,6],[20] ...
  Overflow of [20,30] on insert 30 → split, promote 20 ...
```

## Week 7: Amortized and Worst-Case Analysis, Heuristics

Amortized analysis averages cost over sequences: aggregate, accounting (credits), and potential (`Φ`) methods. Self-organizing lists use move-to-front (MTF) with 2-competitiveness vs optimal offline order.

### Methods

| Method | Formula | Use |
|--------|---------|-----|
| Aggregate | `total/n` | Stack with multipop |
| Accounting | Charge `ĉᵢ`, keep credit ≥ 0 | Incrementing counter |
| Potential | `ĉᵢ = cᵢ + Φᵢ − Φᵢ₋₁` | Dynamic table, splay |

```python
# Dynamic table doubling: potential Phi = 2*num - size keeps amortized insert O(1).
def amortized_demo():
    size, num, total = 1, 0, 0
    for _ in range(16):
        if num == size: total += size; size *= 2
        num += 1; total += 1
    return total  # ~ 16 + 1+2+4+8 = 31 → ~2 per op
```

## Week 8: External Memory — Blocks and Buffers

RAM is fast but small; disks move whole blocks (`B` items). I/O complexity counts block transfers, not CPU steps. Buffer pools (LRU/CLOCK) and blocking layouts decide real performance.

### I/O Model

| Operation | I/O cost |
|-----------|----------|
| Scan N items | `O(N/B)` |
| Binary search, unblocked | `O(log₂ N)` I/Os |
| B-tree search | `O(log_B N)` I/Os |
| Sort (2-way merge) | `O((N/B) log₂(N/B))` |

```python
# Simulate block reads: count transfers for linear scan vs indexed access.
B = 64
def scan_ios(n): return (n + B - 1) // B
def btree_ios(n, fanout=64):
    import math; return math.ceil(math.log(n, fanout)) if n > 1 else 1
print(scan_ios(1_000_000), btree_ios(1_000_000))  # 15625 vs 4
```

## Week 9: Sequential and Random-Access Files

Files persist records: sequential files (ordered arrival or sorted) suit batch scans; random-access files compute offsets (`base + i·R`) for `O(1)` positional reads. Fixed vs variable records trade simplicity for space.

### Layouts

| Organization | Access | Insert |
|--------------|--------|--------|
| Unordered sequential | Scan | Append `O(1)` |
| Sorted sequential | Scan + binary-ish | Rewrite/shift |
| Random (relative) | `seek(i)` direct | Slot reuse via free list |

```python
import struct
REC = struct.Struct("<i20s")  # id + name
def write_records(path, rows):
    with open(path, "wb") as f:
        for _id, name in rows:
            f.write(REC.pack(_id, name.encode()[:20].ljust(20, b"\x00")))
def read_record(path, i):
    with open(path, "rb") as f:
        f.seek(i * REC.size)
        _id, raw = REC.unpack(f.read(REC.size))
        return _id, raw.rstrip(b"\x00").decode()
```

## Week 10: Heap Files and Hash Files

Heap files store records in arrival order with a page directory; hash files map keys to buckets (`h(k)`) with overflow chains or dynamic schemes (extendible/linear hashing). Load factor and bucket size govern performance.

### Hash File Anatomy

| Piece | Role |
|-------|------|
| Hash `h(k)` | Bucket number |
| Primary pages | First `b` slots per bucket |
| Overflow chain | Extra pages on collision |
| Directory (extendible) | Doubles on split, global/local depth |

```python
class HashFile:
    def __init__(self, m=8):
        self.m = m; self.buckets = [[] for _ in range(m)]
    def h(self, k): return hash(k) % self.m
    def insert(self, k, v): self.buckets[self.h(k)].append((k, v))
    def find(self, k):
        b = self.buckets[self.h(k)]
        return [v for kk, v in b if kk == k]
```

## Week 11: Ordered and Indexed Sequential Files

Sorted + sparse index = indexed sequential (ISAM): cylinder/track levels route to data pages with overflow areas. Great for range scans and mostly-static data; heavy inserts degrade into overflow chains needing reorganization.

### ISAM Levels

| Level | Content |
|-------|---------|
| Master index | Cylinder ranges |
| Cylinder index | Track starts per cylinder |
| Track index | Page offsets + high keys |
| Data + overflow | Sorted pages + chain |

```text
Search  K=48210:
  master → cylinder 3 (40000–59999)
  cylinder → track 7 (47000–48999)
  track → page 12 (48000–48399) → binary search + overflow follow
```

## Week 12: B+ Trees for Indexed Files

B+ trees separate routing (internal keys) from data (leaf pages linked for scans). High fanout → 3–4 levels for millions of rows; inserts/deletes split/merge with redistribution. The workhorse of real DBMS indexes.

### B+ vs B-Tree

| Aspect | B-tree | B+ tree |
|--------|--------|---------|
| Data | Every node | Leaves only |
| Scan | Tree walk | Leaf linked list |
| Fanout | Lower | Higher (keys only) |
| Range | Slower | <span class="badge">Fast sequential</span> |

```python
# Leaf-level sketch: doubly linked leaves enable [lo, hi] scans.
class Leaf:
    def __init__(self): self.keys = []; self.vals = []; self.next = None
def range_scan(first_leaf, lo, hi):
    out, leaf = [], first_leaf
    while leaf:
        out += [(k, v) for k, v in zip(leaf.keys, leaf.vals) if lo <= k <= hi]
        if leaf.keys and leaf.keys[-1] > hi: break
        leaf = leaf.next
    return out
```

## Week 13: Dense Multi-Indexed Files

One ordering is never enough: secondary (often dense) indexes map each key value to record pointer(s) — inverted lists for duplicates. Multi-index queries intersect posting lists; selectivity decides the plan.

### Secondary Index Design

| Choice | Effect |
|--------|--------|
| Dense | Entry per record; bigger, precise |
| Sparse | Entry per block; smaller, scans |
| Clustered | Data ordered by key (one only) |
| Unclustered | Any order; pointer hops |

```python
# Inverted index: surname → sorted posting list; AND = two-pointer intersect.
def intersect(a, b):
    i = j = 0; out = []
    while i < len(a) and j < len(b):
        if a[i] == b[j]: out.append(a[i]); i += 1; j += 1
        elif a[i] < b[j]: i += 1
        else: j += 1
    return out

post = {"novak": [1, 5, 9], "brno": [5, 9, 12]}
print(intersect(post["novak"], post["brno"]))  # [5, 9]
```

### Balanced Trees

| Tree | Fix on insert | Height |
|------|---------------|--------|
| AVL | Rotate (LL/RR/LR/RL) | ≤ 1.44 log n |
| Treap | Rotate by priority | Expected O(log n) |
| Splay | Zig/zig-zig/zig-zag | Amortized O(log n) |
| B-tree t | Split full child | O(log_t n) |
| B+ tree | Split leaf, promote copy | O(log_B n) I/Os |

## Week 1: Spring Boot Intro — DI, IoC, Annotations

Spring Boot wires applications via Inversion of Control: the container creates beans and injects dependencies. Starter dependencies, auto-configuration, and layered annotations turn a `main` method into a web app.

### Core Annotations

| Annotation | Role |
|------------|------|
| `@SpringBootApplication` | Config + component scan + auto-config |
| `@Component / @Service / @Repository` | Stereotype beans |
| `@Autowired` | Injection point (prefer constructor) |
| `@Value / @ConfigurationProperties` | Externalized config |

```java
// Constructor injection — preferred: explicit, testable, immutable.
@Service
public class OrderService {
    private final OrderRepository orders;
    public OrderService(OrderRepository orders) { this.orders = orders; }
    public Order place(Order o) { return orders.save(o); }
}
```

> **Rule:** Prefer constructor injection — field injection hides dependencies and complicates tests.

## Week 2: Controllers, Lombok, Spring Web, DevTools

Controllers map HTTP to methods (`@GetMapping`, `@PostMapping`, ...); Lombok removes boilerplate (`@Getter`, `@Builder`); DevTools gives hot reload. Clean controllers delegate to services and return proper status codes.

### Mapping Cheat Sheet

| Annotation | Example |
|------------|---------|
| `@GetMapping("/api/users/{id}")` | Read one (`@PathVariable`) |
| `@GetMapping("/api/users")` | List (`@RequestParam` filters) |
| `@PostMapping` + `@RequestBody` | Create → `201 Created` |
| `@PutMapping / @PatchMapping` | Replace / partial update |
| `@DeleteMapping` | Remove → `204 No Content` |

```java
@RestController
@RequestMapping("/api/products")
@RequiredArgsConstructor
public class ProductController {
    private final ProductService service;

    @GetMapping("/{id}")
    public ProductDto get(@PathVariable Long id) { return service.get(id); }

    @PostMapping
    @ResponseStatus(HttpStatus.CREATED)
    public ProductDto create(@Valid @RequestBody ProductDto dto) {
        return service.create(dto);
    }
}
```

## Week 3: Docker, Spring Data, JPA, Repository, DTO

Postgres runs in Docker; JPA maps entities; Spring Data repositories provide queries; DTOs decouple API contracts from persistence. MapStruct or manual mappers sit at the boundary.

### Layering

| Layer | Contains |
|-------|----------|
| Entity | `@Entity`, relations, no JSON leaks |
| Repository | `JpaRepository`, derived/explicit queries |
| Mapper | Entity ⟷ DTO conversion |
| Service | Transactions (`@Transactional`), rules |

```java
@Entity
@Getter @Setter @NoArgsConstructor
public class Product {
    @Id @GeneratedValue private Long id;
    private String name;
    private double price;
}

public interface ProductRepository extends JpaRepository<Product, Long> {
    List<Product> findByNameContainingIgnoreCase(String q);
    @Query("SELECT p FROM Product p WHERE p.price BETWEEN :lo AND :hi")
    List<Product> inRange(@Param("lo") double lo, @Param("hi") double hi);
}
```

## Week 4: REST API, Validation, JWT Security

Good REST uses nouns, plural collections, and status codes; Bean Validation rejects bad input early; JWT (access + refresh) statelessly carries identity and roles behind a filter chain with password hashing.

### Status & Validation

| Situation | Status |
|-----------|--------|
| Created | `201 + Location` |
| Bad input | `400 + field errors` |
| Unauthorized | `401` |
| Forbidden | `403` |
| Not found | `404` |

```java
public record RegisterDto(
    @NotBlank String username,
    @Email String email,
    @Size(min = 8) String password) {}

@RestControllerAdvice
public class ApiErrors {
    @ExceptionHandler(MethodArgumentNotValidException.class)
    @ResponseStatus(HttpStatus.BAD_REQUEST)
    public Map<String, String> invalid(MethodArgumentNotValidException ex) {
        Map<String, String> m = new HashMap<>();
        ex.getBindingResult().getFieldErrors()
          .forEach(e -> m.put(e.getField(), e.getDefaultMessage()));
        return m;
    }
}
```

```java
// JWT login sketch (filter validates Bearer, sets SecurityContext)
@PostMapping("/auth/login")
public TokenDto login(@Valid @RequestBody LoginDto dto) {
    authenticationManager.authenticate(
        new UsernamePasswordAuthenticationToken(dto.username(), dto.password()));
    return tokens.issue(dto.username());
}
```

## Week 5: Unit and Integration Testing

Test pyramid: fast unit tests (Mockito) for services, slice tests (`@WebMvcTest`) for controllers, and full integration (`@SpringBootTest` + Testcontainers) for repositories and security flows.

### Test Stack

| Scope | Tooling |
|-------|---------|
| Unit | JUnit 5 + Mockito + AssertJ |
| Web slice | `@WebMvcTest` + MockMvc |
| Data | `@DataJpaTest` / Testcontainers Postgres |
| Full API | `@SpringBootTest` + MockMvc + JWT helper |

```java
@ExtendWith(MockitoExtension.class)
class OrderServiceTest {
    @Mock OrderRepository repo;
    @InjectMocks OrderService service;

    @Test
    void placesOrder() {
        when(repo.save(any())).thenAnswer(i -> i.getArgument(0));
        assertNotNull(service.place(new Order()));
        verify(repo).save(any());
    }
}
```

```java
@SpringBootTest
@AutoConfigureMockMvc

           .andExpect(status().isUnauthorized());
```

## Week 6: JavaScript/TypeScript and Async

Modern frontends are TypeScript: strict types, narrowing, generics, plus promise-based async (`async/await`, `Promise.all`, AbortController). This week rebuilds JS fundamentals before React.

### Async Patterns

| Pattern | Use |
|---------|-----|
| `await fetch(...)` | Sequential I/O |
| `Promise.all([...])` | Parallel independent calls |
| `AbortController` | Cancel stale requests |
| `try/catch + Result` | Typed error paths |

```typescript
export interface Product { id: number; name: string; price: number; }

export async function getProducts(signal?: AbortSignal): Promise<Product[]> {
  const res = await fetch("/api/products", { signal });
  if (!res.ok) throw new Error(`HTTP ${res.status}: ${await res.text()}`);
  return (await res.json()) as Product[];
}

// Parallel load with graceful partial failure
const [products, cats] = await Promise.all([
  getProducts().catch(() => []),
  getCategories().catch(() => []),
]);
```

## Week 7: React Intro — Basic Concepts

React renders UI from state via components; Vite + strict TypeScript is the course baseline. JSX, props-down/events-up, and the `useState`/`useEffect` pair carry the first apps before routers and servers enter.

### Mental Model

| Concept | Rule |
|---------|------|
| Components | Pure functions of props + state |
| JSX | One root, `{}` for expressions |
| State | `useState` for local; lift when shared |
| Effects | `useEffect` for sync with outside (fetch, timers) |

```tsx
import { useEffect, useState } from "react";
import { getProducts, type Product } from "./api";

export function ProductList() {
  const [items, setItems] = useState<Product[]>([]);
  const [error, setError] = useState<string | null>(null);

  useEffect(() => {
    const ac = new AbortController();
    getProducts(ac.signal).then(setItems, (e) => setError(String(e)));
    return () => ac.abort();
  }, []);

  if (error) return <p role="alert">Failed: {error}</p>;
  return <ul>{items.map((p) => <li key={p.id}>{p.name} — {p.price} Kč</li>)}</ul>;
}
```

## Week 8: Components, JSX, Props, State

Reusable components need typed props, composition (`children`), controlled inputs, and custom hooks. State lives as low as possible; shared state lifts to the nearest common ancestor or context.

### Patterns

| Pattern | Example |
|---------|---------|
| Controlled input | `value + onChange`, single source |
| Composition | `<Card><ProductForm/></Card>` |
| Custom hook | `useProducts()` hides fetch logic |
| Lifting | Filter state in parent, list dumb |

```tsx
interface Props { value: string; onChange: (v: string) => void; }

export function SearchBox({ value, onChange }: Props) {
  return (
    <label>Search{" "}
      <input value={value} onChange={(e) => onChange(e.target.value)} placeholder="laptop…" />
    </label>
  );
}

export function useDebounced<T>(value: T, ms = 300): T {
  const [v, setV] = useState(value);
  useEffect(() => {
    const t = setTimeout(() => setV(value), ms);
    return () => clearTimeout(t);
  }, [value, ms]);
  return v;
}
```

## Week 9: Fetch API, Axios, Security

Browsers call secured APIs with `Authorization: Bearer <jwt>`; Axios instances centralize base URL, token attach, and 401 refresh-and-retry. Tokens live in memory (or httpOnly cookies) — never in `localStorage` for XSS-exposed apps.

### Client Security Checklist

```typescript
import axios from "axios";

export const http = axios.create({ baseURL: "/api", timeout: 8000 });

let access = ""; // memory only
http.interceptors.request.use((c) => {
  if (access) c.headers.Authorization = `Bearer ${access}`;
  return c;
});
http.interceptors.response.use(
  (r) => r,
  async (err) => {
    if (err.response?.status === 401 && !err.config._retry) {
      err.config._retry = true;
      access = await refreshAccess(); // POST /auth/refresh (cookie)
      return http(err.config);
    }
    throw err;
  }
);
```

| Storage | XSS risk | CSRF risk | Verdict |
|---------|----------|-----------|---------|
| localStorage | <span class="badge danger">High</span> | Low | Avoid for tokens |
| Memory | Low | Low | <span class="badge">Preferred</span> |
| httpOnly cookie | Low | Needs SameSite+CSRF | Good alternative |

## Week 10: React Testing

React Testing Library tests behavior ("user sees/filters/buys"), not internals: render, interact with `userEvent`, assert visible outcomes, mock network with MSW. Vitest runs it fast in CI.

### Query Priority

| Priority | Query | Why |
|----------|-------|-----|
| 1 | `getByRole` | Accessible = testable |
| 2 | `getByLabelText` | Form-friendly |
| 3 | `getByText` | Content checks |
| Avoid | `testId` | Last resort |

```tsx
import { render, screen } from "@testing-library/react";
import userEvent from "@testing-library/user-event";
import { ProductList } from "./ProductList";

test("filters products", async () => {
  render(<ProductList />);
  await userEvent.type(screen.getByLabelText(/search/i), "phone");
  expect(await screen.findByText(/phone/i)).toBeInTheDocument();
  expect(screen.queryByText(/laptop/i)).not.toBeInTheDocument();
});
```

## Week 11: Advanced React — Query and Hook Form

Server state (cache, refetch, pagination) belongs to React Query; form state (values, errors, submit) to Hook Form + Zod. Together they remove most `useEffect` fetching and hand-rolled validation.

### Stack

| Concern | Tool |
|---------|------|
| Fetch/cache | `@tanstack/react-query` |
| Forms | `react-hook-form` + `zod` + resolvers |
| Mutations | `useMutation` + query invalidation |

```tsx
import { useQuery, useMutation, useQueryClient } from "@tanstack/react-query";
import { useForm } from "react-hook-form";
import { z } from "zod";
import { zodResolver } from "@hookform/resolvers/zod";

const Schema = z.object({
  name: z.string().min(2),
  price: z.coerce.number().positive(),
});
type Form = z.infer<typeof Schema>;

export function ProductForm() {
  const qc = useQueryClient();
  const { register, handleSubmit, formState: { errors } } =
    useForm<Form>({ resolver: zodResolver(Schema) });
  const save = useMutation({
    mutationFn: (v: Form) => http.post("/products", v),
    onSuccess: () => qc.invalidateQueries({ queryKey: ["products"] }),
  });
  return (
    <form onSubmit={handleSubmit((v) => save.mutate(v))}>
      <input {...register("name")} />
      {errors.name && <small>{errors.name.message}</small>}
      <input {...register("price")} type="number" />
      <button disabled={save.isPending}>Save</button>
    </form>
  );
}
```

## Code Review Guide

### What to Look For

#### 1. Backend layering
- Controllers thin? Business in `@Transactional` services? DTOs at boundary?

#### 2. Security
- Passwords hashed? JWT expiry + refresh? Authz by role, not just authn?

#### 3. Frontend hygiene
- No `useEffect` fetch soup (Query used)? Forms validated both sides?

<div class="review-note">

<strong>🔍 Practice Review:</strong> A controller calls `repository.save(entity)` directly with the `@RequestBody` entity and stores passwords in plain text. Issues: mass-assignment, no validation, no hashing, no DTO. Fix: introduce `RegisterDto` + `@Valid`, map to entity, `passwordEncoder.encode()`, return `201 + Location` without the hash.

```java
// fixed sketch:
var e = new User(dto.username(), encoder.encode(dto.password()), Set.of(Role.USER));
repo.save(e);
return ResponseEntity.created(URI.create("/api/users/" + e.getId())).build();
```

### React + Query

```tsx
// list with server state
const { data, isPending, error } = useQuery({
  queryKey: ["products", q, page],
  queryFn: () => http.get("/products", { params: { q, page } }).then((r) => r.data),
});
// mutate then refresh
const qc = useQueryClient();
const del = useMutation({
  mutationFn: (id: number) => http.delete(`/products/${id}`),
  onSuccess: () => qc.invalidateQueries({ queryKey: ["products"] }),
});
```

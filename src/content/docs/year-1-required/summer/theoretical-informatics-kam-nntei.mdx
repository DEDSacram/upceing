## Week 1: Introduction to Language Theory and Grammar

Formal language theory studies sets of strings over finite alphabets. Grammars generate languages; automata recognize them. This week sets notation and historical context from Thue and Post to Chomsky.

### Basic Concepts

- **Alphabet Σ** - Finite non-empty set of symbols, e.g. `Σ = {0, 1}`.
- **Word** - Finite sequence over Σ; empty word denoted `ε`. Length `|w|`.
- **Language** - Any subset `L ⊆ Σ*`, where `Σ*` is the set of all words.

| Operation | Notation | Example |
|-----------|----------|---------|
| Concatenation | `u · v` | `ab · cd = abcd` |
| Power | `Σⁿ` | `Σ² = {aa,ab,ba,bb}` |
| Kleene star | `L*` | `{a}* = {ε,a,aa,...}` |
| Union | `L₁ ∪ L₂` | `{a} ∪ {b} = {a,b}` |

### Grammars

A grammar is `G = (N, T, P, S)` where `N` are nonterminals, `T` terminals, `P` productions, `S` start symbol.

```text
Example grammar G:
  S → aSb | ε
  L(G) = { aⁿbⁿ | n ≥ 0 }
Derivation: S ⇒ aSb ⇒ aaSbb ⇒ aabb
```

> **Rule:** Always distinguish `ε` (empty word) from `∅` (empty language). `∅* = {ε}`.

## Week 2: Regular Expressions and Regular Sets

Regular expressions (RE) are a compact algebra for describing regular sets. This week covers syntax, semantics, and algebraic laws used to simplify patterns.

### Syntax and Semantics

- **Atoms:** `∅`, `ε`, `a` for each `a ∈ Σ`.
- **Operators:** union `+` (or `|`), concatenation, star `*`.
- Precedence: `*` > concatenation > `+`.

| Expression | Language | Note |
|------------|----------|------|
| `a*` | `{ε,a,aa,...}` | Zero or more |
| `a⁺` | `{a,aa,...}` | One or more, sugar for `aa*` |
| `(a+b)*abb` | Words ending in `abb` | Classic example |
| `(0+1)*0` | Words ending in `0` | Suffix pattern |

### Algebraic Laws

```text
r + s = s + r            (commutativity of union)
(r + s) + t = r + (s + t)
rε = εr = r
r∅ = ∅r = ∅
(r*)* = r*
(r + s)* = (r*s*)*
```

> **Rule:** `+` inside regex means union, not arithmetic addition. Use parentheses to override precedence.

## Week 3: Practical Work with Regular Expressions

Theory meets practice: regex engines in editors, grep, and programming languages. This week focuses on character classes, anchors, groups, and common pitfalls like greedy matching.

### Practical Toolkit

| Construct | Meaning | Example |
|-----------|---------|---------|
| `[a-z]` | Character class | `[0-9]+` matches numbers |
| `[^...]` | Negated class | `[^0-9]` non-digit |
| `^`, `$` | Anchors | `^ab.*` starts with ab |
| `(...)` , `\1` | Group, backreference | `(ab)+\1` |

## Week 4: Regular Languages — Chomsky Type 3

Regular languages sit at level 3 of the Chomsky hierarchy, generated by right-linear (or left-linear) grammars. They are closed under Boolean operations and characterized by the pumping lemma and Myhill–Nerode.

### Right-Linear Grammars

Productions have form `A → wB` or `A → w` where `w ∈ T*`.

```text
Grammar for (a+b)*abb:
  S → aS | bS | aA
  A → bB
  B → b
```

### Closure and Decision Properties

| Property | Regular languages |
|----------|-------------------|
| Union, intersection, complement | <span class="badge">Closed</span> |
| Concatenation, star | <span class="badge">Closed</span> |
| Emptiness, finiteness, membership | <span class="badge">Decidable</span> |
| Inclusion, equivalence | <span class="badge">Decidable</span> |

> **Rule:** To prove non-regularity, use the pumping lemma or Myhill–Nerode — never just intuition.

## Week 5: Finite Automata and Scanners

A finite automaton (FA) is the machine counterpart of regular languages. Deterministic (DFA) and nondeterministic (NFA) variants are equivalent in power; ε-transitions and subset construction connect them. Scanners are built directly from FA.

### DFA vs NFA

| Feature | DFA | NFA |
|---------|-----|-----|
| Transitions | Total function `δ: Q×Σ → Q` | Relation into `P(Q)` |
| ε-moves | No | Allowed in ε-NFA |
| Equivalence | Reachable subset construction | Same power as DFA |
| Minimization | <span class="badge">Unique minimal DFA</span> | PSPACE-hard in general |

### Scanner Example

```python
# Minimal DFA for language (a+b)*abb, states = longest matched suffix
def accepts(w: str) -> bool:
    state = 0
    for c in w:
        if state == 0:
            state = 1 if c == 'a' else 0
        elif state == 1:
            state = 1 if c == 'a' else 2
        elif state == 2:
            state = 1 if c == 'a' else 3
        else:  # state 3 (accepting)
            state = 1 if c == 'a' else 0 if c == 'b' and False else (2 if c == 'b' else 0)
            # simplified: recompute suffix of w ending in prefix of 'abb'
            state = 3 if w[:0] == '' else state
    return state == 3

# Cleaner table-driven version:
TRANS = {(0,'a'):1,(0,'b'):0,(1,'a'):1,(1,'b'):2,(2,'a'):1,(2,'b'):3,(3,'a'):1,(3,'b'):0}
def accepts_table(w):
    s = 0
    for c in w: s = TRANS[(s,c)]
    return s == 3
```

## Week 6: Context-Free Languages — Chomsky Type 2

Context-free grammars (CFG) allow productions `A → α` with a single nonterminal on the left. They describe nested structure (parentheses, expressions) beyond regular power, with Chomsky type 2 strictly above type 3.

### Core Ideas

- **Derivation:** leftmost vs rightmost; ambiguity when two parse trees exist.
- **Inherently ambiguous** languages exist (e.g. `{aⁿbⁿcᵐdᵐ} ∪ {aⁿbᵐcᵐdⁿ}`).
- Closure: union, concatenation, star <span class="badge">closed</span>; intersection, complement <span class="badge danger">not closed</span>.

| Language | Regular? | Context-free? |
|----------|----------|---------------|
| `{aⁿbⁿ}` | No | Yes |
| `{aⁿbⁿcⁿ}` | No | No |
| Palindromes | No | Yes |
| `{ww}` | No | No |

### CFG Example

```text
Balanced parentheses:
  S → SS | (S) | ε

Arithmetic expressions:
  E → E + T | T
  T → T * F | F
  F → (E) | id
```

## Week 7: Derivation Trees, Chomsky and Greibach Normal Forms

Derivation trees make sentence structure explicit. Normal forms restrict productions to enable algorithms (CYK parsing, PDA conversion). Every ε-free CFG converts to Chomsky Normal Form (CNF); every language without ε converts to Greibach Normal Form (GNF).

### Normal Forms

| Form | Allowed productions |
|------|---------------------|
| CNF | `A → BC` or `A → a` (plus `S → ε` optionally) |
| GNF | `A → aα` where `a ∈ T`, `α ∈ N*` |
| 2NF-ish | No unit `A → B` or ε-rules (after cleanup) |

### CNF Conversion Steps

```text
1. Eliminate ε-productions (except S → ε if ε ∈ L).
2. Eliminate unit productions A → B.
3. Remove useless symbols (non-generating, unreachable).
4. Binarize long right-hand sides: A → BCD becomes A → BX, X → CD.
5. Split terminals in binary rules: A → BC stays; A → aB becomes A → XA, X → a.
```

## Week 8: Pushdown Automata and Parsers

Pushdown automata (PDA = finite control + stack) recognize exactly the context-free languages. Deterministic PDA (DPDA) model real parsers (LL/LR); nondeterminism is strictly stronger here, unlike finite automata.

### PDA Essentials

| Component | Role |
|-----------|------|
| Finite control | Like DFA states |
| Stack alphabet Γ | Memory for nesting |
| Transitions | `δ(q, a, Z)` reads input `a`, pops `Z`, pushes string |
| Acceptance | Final state or empty stack (equivalent) |

### PDA for aⁿbⁿ

```text
States: q0 (push), q1 (pop), q2 (accept)
  δ(q0, a, Z0) = (q0, AZ0);  δ(q0, a, A) = (q0, AA)
  δ(q0, ε, Z)  = (q1, Z)      (guess switch point)
  δ(q1, b, A)  = (q1, ε)
  δ(q1, ε, Z0) = (q2, Z0)     (accept)
```

## Week 9: Turing Machines

Turing machines (TM) formalize algorithms: finite control plus an unbounded tape with read/write/move. Variants (multi-tape, nondeterministic) do not add power but simplify design. This week covers the 7-tuple definition and execution traces.

### Definition

`M = (Q, Σ, Γ, δ, q₀, q_accept, q_reject)` where `Γ ⊇ Σ ∪ {␣}` and `δ: Q × Γ → Q × Γ × {L, R}`.

| Concept | Meaning |
|---------|---------|
| Configuration | `u q v` — tape `uv`, head on first symbol of `v` |
| Step | One `δ` application |
| Halting | Entering `q_accept` or `q_reject` |
| Looping | Never halting — distinct from rejecting |

### Trace Example

```text
TM flipping all bits, then halting on blank:
  q0, 0 → q0, 1, R
  q0, 1 → q0, 0, R
  q0, ␣ → qA, ␣, R

Trace on 101:
  q0 101 ⊢ 0 q0 01 ⊢ 01 q0 1 ⊢ 010 q0 ␣ ⊢ 010 qA ␣
```

## Week 11: Turing Machines as Acceptors — Type 0 Languages

Type 0 (recursively enumerable, RE) languages are exactly those accepted by some TM. Decidable (recursive) languages are a strict subset where the TM always halts. Unrestricted grammars generate precisely type 0.

### Landscape

| Class | Machine | Grammar |
|-------|---------|---------|
| Type 3 regular | DFA | Right-linear |
| Type 2 CFL | PDA | Context-free |
| Type 1 CSL | LBA | Context-sensitive |
| Type 0 RE | TM (may loop) | Unrestricted |
| Decidable | TM (always halts) | — |

```text
  (Full grammar is long; key point: left side may have context.)
```

> **Rule:** Accepting ≠ deciding. A recognizer may loop on words outside the language; a decider never loops.

## Week 12: Decidability and Its Limits

Which problems can TMs solve at all? The halting problem is undecidable; reductions transfer undecidability; Rice's theorem kills all nontrivial semantic properties of programs. This week is the conceptual peak of the course.

### Key Results

| Result | Statement |
|--------|-----------|
| Halting undecidable | No TM decides `{⟨M,w⟩ | M halts on w}` |
| `A_TM` undecidable | Acceptance is undecidable but RE |
| Rice theorem | Any nontrivial semantic property of RE languages is undecidable |
| Reduction | `A ≤ₘ B`: decidability of B implies decidability of A |

### Diagonal Proof Sketch

```text
Assume H decides halting. Build D:
  D(⟨M⟩): run H(⟨M,⟨M⟩⟩); if H accepts → loop; else halt.
Then D(⟨D⟩) halts iff D(⟨D⟩) loops. Contradiction. ∎
```

## Week 13: Complexity, P/NP and Intractable Problems

Decidable is not feasible. Complexity classifies decidable problems by resource bounds: `P` (poly time), `NP` (poly verifier / nondet poly time), NP-complete (hardest in NP), plus space classes. Cook–Levin (SAT) anchors all NP-completeness proofs.

### Map

| Class | Intuition | Example |
|-------|-----------|---------|
| `P` | Solvable fast | Sorting, shortest path |
| `NP` | Checkable fast | SAT, Hamiltonian path, TSP-decision |
| `NP-complete` | Hardest in NP | 3-SAT, CLIQUE, Vertex Cover |
| `NP-hard` | At least as hard | Halting (undecidable + hard) |
| `EXP` | Exponential time | Generalized chess |

```python
# Poly verifier for VERTEX-COVER (G, k, certificate C):
def verifies(G, k, C):
    if len(C) > k: return False
    edges = G["edges"]
    return all(u in C or v in C for u, v in edges)
# Runs in O(|E|) → VERTEX-COVER ∈ NP.
```

> **Rule:** To show NP-completeness: (1) prove membership in NP via verifier, (2) reduce a known NP-complete problem in polynomial time.

#### 1. Notation
- Correct quantifiers, alphabets declared, start symbols marked?

- Fewest states/productions? Named blocks for TMs?

## Exam Preparation

### Exam Structure

1. **Written:** 4 tasks — regex+NFA, CFG+CNF or PDA, TM construction, proof/reduction.
2. **Oral:** definitions, theorem statements + proofs (pumping, halting, Cook–Levin sketch).

| Week | Topic | Key Concepts |

<div class="exercise-box">

<strong>📝 Sample Exam Questions:</strong>

1. Convert `(a+b)*abb` to an NFA and then to a minimal DFA.

## Quick Reference Cards

### Regex → Automata → Grammar

```text
regex r  --Thompson-->  ε-NFA  --subset-->  DFA  --minimize-->  minimal DFA
  |                                                              |
  +-- Kleene theorem --------------------------------------------+
Regular expression ⟺ ε-NFA ⟺ DFA ⟺ right-linear grammar
CFG ⟺ PDA (nondeterministic) ; CSL ⟺ LBA ; Type 0 ⟺ TM
```

### Pumping Lemmas

| Lemma | Condition | Use |
|-------|-----------|-----|
| Regular | `w=xyz`, `\|xy\|≤p`, `\|y\|>0`, `xyⁱz∈L` | Kill regularity |
| CFL | `w=uvxyz`, `\|vxy\|≤p`, `\|vy\|>0`, `uvⁱxyⁱz∈L` | Kill context-freeness |

### Complexity Cheat Sheet

| To prove | Do |
|----------|----|
| `L ∈ P` | Poly-time decider |
| `L ∈ NP` | Poly verifier or NTM |
| `L` NP-complete | `L ∈ NP` + `SAT ≤ₚ L` (or 3-SAT, CLIQUE) |
| `L` undecidable | Reduce `A_TM` / HALT to `L` |

## Exam tips

NNPTP
Zápočet
• Není vyžadována docházka na přednášky nebo cvičení
• Pro zisk zápočtu je třeba do termínu zkoušky splnit následující:
o Vytvořit 1 pull request s patchem na kompletní refactoring a vyčištění kódu v 1.
zadaném projektu, pull request musí projít code review a být schválen. Pokud se
vyskytnou připomínky, je nutné patch aktualizovat a vyhovět jim.
o Vytvořit a zahrnout 2 pull requesty (s časovým odstupem) v 2. zadaném projektu,
kde každý pull request představuje jeden ucelený patch zaměřující se na jedinou
konkrétní věc (nová funkcionalita, oprava chyby, oprava stylu kódu, refactoring
struktury kódu, aj.), kde pull request projde skrze proces code review a je
akceptován.
▪ Na druhém projektu budou změnami participovat všichni studenti
předmětu, může se tak stát, že dojde ke konfliktům. V takovém případě je
nutné reagovat na výzvy reviewera a průběžně aktualizovat patch, aby
mohl být zahrnut. Může se rovněž stát, že pokud již jiný student nabídne
takový patch, že bude Váš pull request zamítnut a nebude tedy
akceptován.
o Každý pull request musí splnit následující:
▪ Je nutné vytvořit veřejný fork výchozího projektu, který bude pravidelně
udržován aktualizovaný, aby byly minimalizovány konflikty.
▪ Je nutné, aby PR byl vytvořen na vývojové větvi (není akceptováno nabízení
větví main/master).
▪ PR musí být smysluplně popsán (titulek i popis).
▪ Jazyk PR pro popis může být čeština nebo angličtina.
▪ Nová funkcionalita musí být vždy podpořena sadou jednotkových testů.
▪ V případě 2. projektu se PR vždy zaměřuje na jedinou věc
(funkcionalitu/úpravu/opravu), PR obsahující najednou více aktivit budou
automaticky zamítány.
▪ Při dlouhodobé neaktivitě (> 1 týden) může být PR automaticky zamítnut.
▪ PR nesmí obsahovat navíc nesouvisející soubory (zejména
výsledky/meziprodukty kompilace, dočasné soubory, aj.).
▪ Patch (upravené zdrojové kódy) neobsahuje žádné odkazy k autorství
dotyčné osoby, to je zajištěno samotným verzovacím systémem.
Zkouška
• provedení code review na zadaném příkladě / příkladech
o po sepsání poznámek následuje ústní-konzultační část se zkoušejícím
o code review by se měl zaměřovat na čistotu kódu, strukturu kódu i případné chyby
o hodnocení bude uděleno na základě počtu identifikovaných a zdůvodněných
nedostatků ve vstupním kódu, 60 % představuje hranice pro zisk známky E, další
známky jsou rovnoměrně rozpočítány do 100 %

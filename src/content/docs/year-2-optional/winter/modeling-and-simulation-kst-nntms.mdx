## Week 1: On-line vs Off-line Simulation and Trainers

Off-line simulation answers "what would happen"; on-line simulation answers "what is happening right now, fast enough to act on".

### Definitions

| Aspect | Off-line | On-line |
|--------|----------|---------|
| Coupling to reality | Decoupled, historical/fictional inputs | Coupled to live process or operator |
| Time | Virtual, as-fast-as-possible | Real-time (or scaled), deadlines matter |
| Purpose | Design, analysis, planning | Training, control, decision support |
| Failure mode | Wrong numbers | Missed deadline = wrong behaviour |

### Training Simulators

- **Part-task trainers** — one skill (e.g. pump start-up sequence).
- **Full-scope trainers** — whole control room replica for operators.
- **Hardware-in-the-loop (HIL)** — real controller, simulated plant.
- **Human-in-the-loop** — operator decisions feed back into the scenario.
- Fidelity ladder: physical → functional → psychological fidelity; more is not always better.

### Real-Time Discipline

Fixed step `dt`, worst-case execution time (WCET) per step `< dt`, jitter bounds, deterministic replay via seeded RNG and event logs.

```python
"""Off-line (as-fast-as-possible) vs on-line (real-time paced) loop."""
import time

def simulate_offline(step, n_steps, dt):
    t, state = 0.0, 0.0
    for _ in range(n_steps):
        state = step(state, dt)
        t += dt
    return state

def simulate_online(step, n_steps, dt):
    t, state = 0.0, 0.0
    for _ in range(n_steps):
        deadline = time.perf_counter() + dt
        state = step(state, dt)          # must finish before deadline
        t += dt
        slack = deadline - time.perf_counter()
        if slack < 0:
            raise TimeoutError(f"Overrun at t={t}: {-slack*1000:.1f} ms late")
        time.sleep(slack)
    return state
```

## Week 2: Simulation for Planning — Reactive vs Pro-active

Planners use simulators either to react to the present or to rehearse the future before committing.

### Two Planning Styles

| Style | Question | Simulator role |
|-------|----------|---------------|
| **Reactive** | "A disruption happened — what now?" | Fast what-if evaluation of candidate responses |
| **Pro-active** | "What could happen — are we ready?" | Lookahead search, contingency plans, robustness envelopes |

### Planning Loop with Simulation

```
sense -> update model -> generate options -> simulate each -> rank -> commit -> monitor
```

Key design choices: horizon length, scenario branching factor, evaluation metric (cost, lateness, risk), re-planning trigger.

### Monte Carlo for Plans

Run each candidate plan against sampled disturbances (demand spikes, breakdowns); compare distributions, not point estimates.

```python
"""Reactive choice between two dispatch plans under random demand."""
import random

def simulate_plan(plan: str, demand: list[float]) -> float:
    cost = 0.0
    stock = 10.0
    for d in demand:
        stock += (8.0 if plan == "steady" else 12.0) - d
        if stock < 0:
            cost += 100.0 + abs(stock) * 10  # stockout penalty
            stock = 0
        cost += 1.0 * (8.0 if plan == "steady" else 12.0)
    return cost

def choose_plan(scenarios: int = 500, seed: int = 7) -> dict:
    rng = random.Random(seed)
    totals = {"steady": [], "surge": []}
    for _ in range(scenarios):
        demand = [rng.gauss(9, 3) for _ in range(24)]
        for p in totals:
            totals[p].append(simulate_plan(p, demand))
    return {p: sum(v) / len(v) for p, v in totals.items()}

print(choose_plan())
```

## Week 3: Autonomous Agents and ABAsim

Agent-based simulation replaces one global update function with many local decision-makers interacting — macro-patterns (jams, queues) emerge from micro-rules.

### Agent Definition

An agent is **autonomous** (owns its thread of control), **reactive** (senses), **pro-active** (pursues goals) and **social** (communicates). A thermostat is reactive; a negotiating delivery van is an agent.

### ABAsim Architecture

```
Environment (space, physics, resources)
  |-- Agent 1: sensors | deliberation | actuators | mailbox
  |-- Agent 2: ...
  |-- ...
  |-- Scheduler: time advance + message delivery + conflict resolution
```

ABAsim separates *world dynamics* (movement, queues) from *agent minds* (decisions), so either can be replaced independently.

### Event- vs Process- vs Agent-Driven Control

| Paradigm | State advance | Best for |
|----------|--------------|----------|
| Event-driven | Next-event queue | Queues, networks |
| Process-driven | Coroutine life-cycles | Manufacturing flow |
| Agent-driven | Sense–think–act per agent per tick | Traffic, crowds, markets |

```python
"""Minimal ABAsim-style loop: agents + environment + scheduler."""
from dataclasses import dataclass, field

@dataclass
class Agent:
    name: str
    position: float = 0.0
    speed: float = 1.0
    mailbox: list = field(default_factory=list)

    def sense(self, env) -> dict:
        ahead = [a for a in env.agents if a is not self and 0 < a.position - self.position < 5]
        return {"gap": min((a.position - self.position for a in ahead), default=999.0)}

    def deliberate(self, percept: dict) -> float:
        return 0.0 if percept["gap"] < 2.0 else self.speed  # stop-and-go rule

    def act(self, cmd: float, dt: float) -> None:
        self.position += cmd * dt

class Env:
    def __init__(self, agents): self.agents = agents

def run(env: Env, ticks: int, dt: float = 1.0):
    for _ in range(ticks):
        for a in env.agents:            # sense-deliberate-act, order shuffled in practice
            a.act(a.deliberate(a.sense(env)), dt)
    return [(a.name, round(a.position, 2)) for a in env.agents]

print(run(Env([Agent("v1", 0.0, 2.0), Agent("v2", 6.0, 1.0)]), 5))
```

## Week 4: Agent Decomposition — Internal Components

Real agents are not one function: perception filters noise, deliberation selects intentions, action executes skills, memory keeps state, and communication ports connect the hierarchy.

### Canonical Decomposition

```
sensors -> perception -> beliefs -> deliberation -> intentions -> action -> actuators
              ^                        |    ^                         |
              +------ memory ----------+    +------ mailbox -----------+
```

- **Perception** — denoises, discretises, detects events (e.g. "gap critical").
- **Deliberation** — BDI (beliefs–desires–intentions) or utility maximisation.
- **Action** — skill library with preconditions and durations.
- **Memory** — episodic (what happened) + semantic (map, parameters).

### Agent-Based vs Event/Process Simulators Revisited

| Question | Event-driven | Agent-based |
|----------|-------------|-------------|
| Who decides? | Global scheduler | Each agent locally |
| Heterogeneity? | Awkward | Natural (per-agent rules) |
| Emergence? | Designed in | Observed out |
| Calibration? | Rates/fits | Behaviour + rates |

```python
"""BDI-flavoured agent: beliefs, desires, intentions as explicit state."""
from dataclasses import dataclass, field

@dataclass
class BDIAgent:
    beliefs: dict = field(default_factory=dict)
    desires: list = field(default_factory=lambda: ["keep_gap", "save_fuel"])
    intentions: list = field(default_factory=list)

    def perceive(self, gap: float):
        self.beliefs["gap"] = gap
        self.beliefs["critical"] = gap < 2.0

    def deliberate(self):
        self.intentions = ["brake"] if self.beliefs.get("critical") else ["cruise"]

    def act(self):
        return 0.0 if "brake" in self.intentions else 2.0

a = BDIAgent()
for gap in (5.0, 1.2, 3.0):
    a.perceive(gap); a.deliberate()
    print(gap, "->", a.intentions, a.act())
```

## Week 5: Case Study — Agent-Based Traffic Simulator

Transportation nodes (intersections, ramps, stations) are the classic ABAsim showcase: vehicle agents, link resources, signal controllers, all interacting.

### Model Elements

- **Links** — capacity, free-flow speed, queue storage.
- **Nodes** — conflict matrix (which movements block which), signal phases.
- **Vehicle agents** — origin, destination, desired speed, car-following rule.
- **Controller agent** — phase switching (fixed-time → actuated → adaptive).

### Car-Following in Five Lines

`v_next = min(v_desired, v_leader_gap_rule, v_signal_rule)` — every extension (IDM, Gipps) refines these three terms.

### Minimal Node Simulator

```python
"""Two-approach intersection: N-S green while E-W queues, then swap."""
from collections import deque

class Approach:
    def __init__(self, name): self.name, self.queue = name, deque()
    def arrive(self, vid): self.queue.append(vid)
    def discharge(self): return self.queue.popleft() if self.queue else None

class Signal:
    def __init__(self, phases=("NS", "EW"), green=3): self.phases, self.green = phases, green
    def phase_at(self, t): return self.phases[(t // self.green) % len(self.phases)]

def simulate(arrivals_ns, arrivals_ew, steps=12, green=3):
    ns, ew, sig = Approach("NS"), Approach("EW"), Signal(green=green)
    served = []
    for t in range(steps):
        for v in arrivals_ns.get(t, []): ns.arrive(v)
        for v in arrivals_ew.get(t, []): ew.arrive(v)
        active = ns if sig.phase_at(t) == "NS" else ew
        v = active.discharge()
        if v is not None: served.append((t, active.name, v))
    return served, len(ns.queue) + len(ew.queue)

arr_ns = {0: ["n1", "n2"], 1: ["n3"], 4: ["n4"]}
arr_ew = {0: ["e1"], 2: ["e2", "e3"]}
print(simulate(arr_ns, arr_ew))
```

## Week 6: Message Passing in Hierarchical Agent Systems

Agents rarely talk peer-to-peer only: platoons, intersections and fleets form hierarchies, and addressing determines who hears what.

### Three Addressing Modes

| Mode | Recipients | Example |
|------|-----------|---------|
| **Addressed** | One named agent | "Vehicle n3: stop at line" |
| **Partially addressed** | Attribute group | "All vehicles on link L7: slow to 30" |
| **Non-addressed (broadcast)** | Everyone in scope | "Signal turning red in 3 s" |

### Hierarchy and Scoping

Region → intersection → approach → vehicle. Messages flow down (commands), up (reports) or sideways (negotiation). Scoping rules prevent city-wide spam from a local event.

### Implementation Sketch

```python
"""Hierarchical message bus with three addressing modes."""
from dataclasses import dataclass, field

@dataclass
class Message:
    topic: str
    payload: dict
    to: str | None = None          # addressed
    group: str | None = None       # partially addressed
    # neither set -> broadcast within scope

@dataclass
class AgentNode:
    name: str
    groups: set = field(default_factory=set)
    inbox: list = field(default_factory=list)
    def matches(self, msg: Message) -> bool:
        if msg.to: return msg.to == self.name
        if msg.group: return msg.group in self.groups
        return True  # broadcast

class Bus:
    def __init__(self): self.agents: list[AgentNode] = []
    def send(self, msg: Message):
        for a in self.agents:
            if a.matches(msg): a.inbox.append(msg)

bus = Bus()
for n, g in [("n3", {"link-L7"}), ("n4", {"link-L7"}), ("sig1", {"ctrl"})]:
    bus.agents.append(AgentNode(n, g))
bus.send(Message("slow", {"v": 30}, group="link-L7"))
bus.send(Message("stop", {}, to="n3"))
bus.send(Message("phase", {"in": 3}))
print([(a.name, len(a.inbox)) for a in bus.agents])  # n3:3, n4:2, sig1:1
```

## Week 7: Discrete-Continuous Synchronization

Traffic lights are discrete; vehicle motion is continuous. Hybrid simulators must keep both clocks consistent without missing events (a car crossing the stop line *between* integration steps).

### The Core Problem

- Discrete part jumps at events; continuous part flows via ODEs.
- Dangers: missed zero-crossings, Zeno behaviour (infinite events in finite time), time skew between solvers.

### Synchronization Techniques

| Technique | Idea | Trade-off |
|-----------|------|-----------|
| Fixed small step | Sample everything finely | Simple, wasteful, still misses fast events |
| Zero-crossing detection | Bracket sign changes, bisect | Accurate, needs continuous monitors |
| Quantized-state (QSS) | Update on state change, not time | Efficient for sparse activity |
| Co-simulation master (FMI-style) | Orchestrates sub-simulators, rollback on mismatch | Standardised, master complexity |

```python
"""Hybrid loop: integrate motion, detect stop-line crossing between steps."""
def simulate_hybrid(x0=20.0, v=-5.0, stop_line=0.0, dt=0.5, steps=10):
    x, t, events = x0, 0.0, []
    for _ in range(steps):
        x_new = x + v * dt                      # Euler integration (continuous part)
        if x > stop_line >= x_new:              # zero-crossing guard (discrete event)
            frac = (x - stop_line) / (x - x_new)
            events.append(round(t + frac * dt, 3))
            x_new = stop_line                   # clamp: vehicle stops at line
            v = 0.0                             # signal red -> discrete state change
        x, t = x_new, t + dt
    return events, round(x, 3)

print(simulate_hybrid())  # crossing time localised inside the step
```

## Week 8: AI and Soft Computing in Simulators

Agents must decide under uncertainty with incomplete data — the home turf of fuzzy logic, heuristics, metaheuristics and learning.

### Toolbox Map

| Method | Role in simulator | Example |
|--------|-------------------|---------|
| Fuzzy control | Smooth rules from vague inputs | Signal green extension from "long queue" |
| Heuristics | Fast decent decisions | Nearest-vehicle-first dispatch |
| Metaheuristics (GA, SA, ACO) | Offline optimisation of parameters | Signal timing plans |
| Reinforcement learning | Online policy learning | Adaptive ramp metering |
| Neural nets | Surrogate models of slow physics | Emissions estimator |

### Fuzzy Controller Example

```python
"""Fuzzy green-extension: long queue AND short wait -> extend a lot."""
def triangular(x, a, b, c):
    return max(0.0, min((x - a) / (b - a + 1e-9), (c - x) / (c - b + 1e-9)))

def fuzzy_extend(queue: float, wait: float) -> float:
    long_q, short_w = triangular(queue, 5, 10, 15), triangular(wait, 0, 5, 10)
    med_q, med_w = triangular(queue, 0, 5, 10), triangular(wait, 5, 15, 25)
    extend_big, extend_small = min(long_q, short_w), min(med_q, med_w)
    return round((extend_big * 6 + extend_small * 2) / max(1e-9, extend_big + extend_small), 2)

print(fuzzy_extend(queue=12, wait=3))   # -> ~6 s
print(fuzzy_extend(queue=4, wait=18))   # -> ~2 s
```

### Heuristic vs Optimal

Simulators evaluate heuristics *in silico* before deployment: a 5 % worse plan that runs 100× faster often wins on-line.

## Week 9: Petri Nets I — Foundations

Petri nets model concurrency, choice, synchronization and resource contention graphically *and* formally — ideal for simulator components.

### Definition

A net `N = (P, T, F, W, M0)`: places `P`, transitions `T`, arcs `F`, weights `W`, initial marking `M0`. Tokens in places = distributed state.

### Enabling and Firing Rules

- **Enabled**: every input place holds ≥ arc weight tokens.
- **Firing**: consumes input tokens, produces output tokens (atomic, non-deterministic choice on conflict).

### Reachability Graph

Nodes = markings reachable from `M0`; edges = firings. Answers boundedness (finite graph?), deadlocks (sink nodes?), liveness.

```python
"""Minimal Petri-net engine: enabling, firing, reachability BFS."""
from collections import deque

class Net:
    def __init__(self, places, transitions, arcs_in, arcs_out, marking):
        self.places, self.transitions = places, transitions
        self.inp, self.out, self.m0 = arcs_in, arcs_out, dict(marking)

    def enabled(self, marking, t):
        return all(marking.get(p, 0) >= w for p, w in self.inp.get(t, {}).items())

    def fire(self, marking, t):
        m = dict(marking)
        for p, w in self.inp.get(t, {}).items(): m[p] -= w
        for p, w in self.out.get(t, {}).items(): m[p] = m.get(p, 0) + w
        return m

    def reachability(self):
        seen, q = set(), deque([tuple(sorted(self.m0.items()))])
        seen.add(q[0])
        while q:
            key = q.popleft()
            m = dict(key)
            for t in self.transitions:
                if self.enabled(m, t):
                    k = tuple(sorted(self.fire(m, t).items()))
                    if k not in seen: seen.add(k); q.append(k)
        return seen

net = Net(["p1", "p2"], ["t1"],
          {"t1": {"p1": 1}}, {"t1": {"p2": 1}}, {"p1": 2, "p2": 0})
print(sorted(net.reachability()))
```

## Week 10: Petri Nets II — Processes and Components

Beyond analysis: use nets as *executable specifications* of technological processes and simulator blocks.

### Modelling Patterns

| Pattern | Net shape | Use |
|---------|-----------|-----|
| Sequence | Chain | Assembly steps |
| Choice / conflict | Shared input place | Routing, failures |
| Fork–join | Split + sync transition | Parallel tasks |
| Mutual exclusion | Semaphore place | Shared resource |
| Bounded buffer | Producer/consumer + capacity place | Queues |

### From Net to Simulator Component

Each transition = guarded action with duration; the net *is* the control logic, the tokens *are* the state — no hidden flags.

```python
"""Producer-consumer with capacity 2 as an executable net fragment."""
prod_cons = Net(
    ["free", "buf", "ready"], ["produce", "consume"],
    {"produce": {"free": 1}, "consume": {"buf": 1}},
    {"produce": {"buf": 1}, "consume": {"free": 1, "ready": 1}},
    {"free": 2, "buf": 0, "ready": 0},
)
graph = prod_cons.reachability()
print("markings:", len(graph))
# Invariant check: free + buf == 2 in every marking?
print(all(dict(m)["free"] + dict(m)["buf"] == 2 for m in graph))
```

### Coloured and Timed Extensions

- **Coloured nets** — tokens carry data (vehicle IDs, job types).
- **Timed nets** — transitions have delays (processing times, travel times).
- **Hierarchical nets** — subnets hide detail; interfaces stay small.

## Week 11: Distributed and Parallel Simulation

One machine is too slow or too small — partition the model across logical processes (LPs) and keep virtual time coherent.

### Why Distribute Agent Sims

- Scale (millions of agents), speed (multi-core/cluster), geography (federated trainers), fault isolation.

### Partitioning

| Strategy | Idea | Risk |
|----------|------|------|
| Spatial | Region per LP | Border chatter |
| Functional | Subsystem per LP | Load imbalance |
| Agent-based | Agent groups migrate | Migration cost |

Goal: balance load, minimise cross-LP messages, maximise **lookahead** (how far an LP can safely advance without outside input).

### Time Management Overview

- **Conservative** (Week 12) — never advance past a possible incoming event; safe, can deadlock/starve on zero lookahead.
- **Optimistic** (Week 13) — advance freely, roll back on causality violation; fast, needs state saving + anti-messages.

```python
"""Two-LP ping-pong: the causality problem in one screen."""
import heapq

class LP:
    def __init__(self, name): self.name, self.clock, self.inbox = name, 0.0, []
    def send(self, other, t, payload): heapq.heappush(other.inbox, (t, payload))
    def step(self):
        if self.inbox:
            t, p = heapq.heappop(self.inbox)
            self.clock = max(self.clock, t)   # local causality: never go backwards here
            return (self.clock, p)
        self.clock += 1.0
        return (self.clock, None)

a, b = LP("A"), LP("B")
a.send(b, 5.0, "hello")
print(a.step(), b.step(), b.step())  # B jumps to 5.0 on message arrival
```

## Week 12: Conservative Synchronization

Conservative protocols guarantee "no causality error ever" by blocking: an LP advances only when every input channel provably holds no earlier event.

### Chandy-Misra-Bryant (CMB)

- FIFO channels, each LP waits until all input queues are non-empty, then processes the smallest timestamp.
- **Deadlock risk**: empty channels block cycles → fix with **null messages** carrying lookahead promises ("nothing before T+L").

### Lookahead Is Everything

Lookahead `L` = minimum simulated delay on a path (link travel time, service time). Larger `L` → fewer null messages → more parallelism. Zero lookahead → serialization.

### Null-Message Sketch

```python
"""CMB-style LP with lookahead-based null messages (single channel demo)."""
import heapq

class CL:
    def __init__(self, lookahead): self.q, self.lookahead, self.clock = [], lookahead, 0.0
    def receive(self, t, real=True): heapq.heappush(self.q, (t, real))
    def safe_time(self):
        return self.q[0][0] if self.q else float("inf")
    def advance(self):
        t, real = heapq.heappop(self.q)
        self.clock = t
        # promise downstream: nothing earlier than clock + lookahead
        return (f"null entertaining t>={t + self.lookahead}", real)

lp = CL(lookahead=2.0)
lp.receive(3.0); lp.receive(7.0, real=False)
print("safe:", lp.safe_time(), "->", lp.advance(), "clock:", lp.clock)
```

### When Conservative Wins

Sparse events with good lookahead (networks with propagation delay, manufacturing with service times), hard real-time federations (HLA time-managed federates), systems where rollback state is huge.

## Week 13: Optimistic Synchronization

Time Warp bets that causality violations are rare: LPs race ahead, detect stragglers, roll back, cancel wrong messages with anti-messages, and garbage-collect via Global Virtual Time (GVT).

### Jefferson's Time Warp

1. **Execute freely** — process smallest local event, save state snapshots.
2. **On straggler** (message with `t < clock`) — roll back to last snapshot `≤ t`, re-execute.
3. **Cancel errors** — send anti-messages annihilating wrongly sent messages (possibly cascading rollbacks).
4. **Commit via GVT** — `GVT = min(all LP clocks, in-transit timestamps)`; states older than GVT are fossil-collected, I/O older than GVT is committed.

### State Saving Options

| Method | Cost model | Best when |
|--------|-----------|-----------|
| Copy state saving | Memory-heavy, simple | Small states |
| Incremental / event sourcing | Log deltas, replay | Large states, rare rollback |
| Reverse computation | Zero memory, CPU on rollback | Invertible events |

```python
"""Time-Warp rollback toy: snapshots + straggler + anti-message log."""
class OptimisticLP:
    def __init__(self): self.clock, self.snaps, self.sent, self.log = 0.0, {0.0: 0}, [], []
    def run_to(self, t, delta):
        self.snaps[self.clock] = self.log.copy()
        self.clock = t
        self.log.append(delta)
        self.sent.append((t, delta))
    def straggler(self, t, delta):
        # roll back to latest snapshot <= t
        base = max(s for s in self.snaps if s <= t)
        self.clock = t
        self.log = self.snaps[base] + [delta]
        anti = [m for m in self.sent if m[0] > base]  # messages to cancel
        self.sent = [m for m in self.sent if m[0] <= base]
        return f"rolled back to {base}, anti-messages: {anti}"

lp = OptimisticLP()
lp.run_to(5.0, "a"); lp.run_to(9.0, "b")
print(lp.straggler(6.0, "straggler!"), "| clock:", lp.clock, "| log:", lp.log)
```

### GVT and Fossil Collection

GVT computation (Mattern, Samadi) runs concurrently; everything below GVT is certain history — safe to delete snapshots, release I/O, confirm billing. Infrequent GVT → memory blowup; too frequent → overhead.

## Week 1: SDN — Separating Control and Data Planes

SDN removes distributed routing intelligence from switches into a logically centralised controller; switches become fast match-action tables programmed via OpenFlow.

### Architecture

```
Application layer (routing, firewall, LB apps)
        ^  northbound (REST API)
Controller (RYU / Floodlight / ONOS / ODL): topology, paths, policy
        v  southbound (OpenFlow, NETCONF, P4Runtime)
Data plane (Open vSwitches): flow tables -> forward / drop / modify
```

### OpenFlow Match-Action Pipeline

| Table step | Example match | Example action |
|------------|---------------|----------------|
| Ingress port + MAC | `in_port=1, dl_dst=...` | forward to controller |
| L3 routing | `ip, nw_dst=10.0.0.0/24` | output port 2 |
| ACL | `tcp, tp_dst=22` | drop |
| Rewrite | `vlan_tci=...` | push VLAN, output |

> **Rule:** Every SDN decision must be traceable to a flow entry — `ovs-ofctl dump-flows` is the ground truth, not the dashboard.

### Mininet + RYU Hands-On

```python
# labs/01-virtual-network-deployment/mininet_remote.py (excerpt, full file in upce/NNTPS/)
from mininet.topo import Topo
from mininet.net import Mininet
from mininet.node import RemoteController

class TwoSwitchTopo(Topo):
    def build(self):
        s1, s2 = self.addSwitch('s1'), self.addSwitch('s2')
        h1, h2 = self.addHost('h1'), self.addHost('h2')
        self.addLink(h1, s1); self.addLink(h1, s2)
        self.addLink(h2, s1); self.addLink(h2, s2)
        self.addLink(s1, s2)

if __name__ == '__main__':
    net = Mininet(topo=TwoSwitchTopo(), controller=RemoteController('c0', ip='127.0.0.1'))
    net.start(); net.pingAll(); net.stop()
```

## Week 2: NFV and Service Chaining

NFV virtualises middleboxes (firewall, NAT, DPI, vEPC) as software VNFs on commodity servers; MANO orchestrates their lifecycle; service chaining steers traffic through ordered VNF sequences.

### ETSI MANO Blocks

| Block | Role | Example |
|-------|------|---------|
| NFVO | End-to-end service orchestration | OSM, ONAP |
| VNFM | VNF lifecycle (instantiate, scale, heal) | Tacker, Juju |
| VIM | Virtualised infrastructure (compute/net/storage) | OpenStack, K8s |

### Service Function Chaining

Classifier tags packets (NSH header) → forwarders walk the chain `firewall -> DPI -> NAT` → declassifier strips tags. Ordering and symmetry (return path) are the hard parts.

```yaml
# VNF descriptor excerpt (ETSI SOL001-style, TOSCA flavour)
topology_template:
  node_templates:
    vFirewall:
      type: tosca.nodes.nfv.VNF
      properties:
        descriptor_id: fw-v1
        flavour: small        # 2 vCPU / 4 GB
      requirements:
        - virtual_link: net-mgmt
        - virtual_link: net-wan
      interfaces:
        Vnflcm:
          instantiate: scripts/fw_boot.sh
          scale: scripts/fw_scale.sh
```

```bash
# Chain check on the wire: tag, forward, verify order with tcpdump marks
sudo ovs-ofctl -O OpenFlow13 add-flow s1 "ip,nw_dst=10.0.0.0/24 actions=mod_nw_tos:8,output:2"
sudo tcpdump -i s1-eth2 -v 'ip[1] & 0xfc == 8' -c 5
```

## Week 3: IPv6 in Practice

IPv6 is not IPv4 with longer addresses: no NAT-by-default, no broadcast, SLAAC autonomy, extension-header chains and mandatory first-hop security thinking.

### Addressing Plan

| Block | Purpose | Example |
|-------|---------|---------|
| `2001:db8::/32` | Documentation (never route publicly) | Labs, slides |
| `fd00::/8` (ULA) | Private, locally unique | `fd00:lab:1::/48` per site |
| `fe80::/10` | Link-local (ND, routing protocols) | Auto on every interface |
| `ff00::/8` | Multicast (replaces broadcast) | `ff02::1` all-nodes |

Plan nibbles on `/48` per site → `/64` per LAN (SLAAC needs a full 64 bits).

### Key Mechanisms

- **SLAAC + RDNSS** — plug-and-play addresses; control with RA guard + `AdvAutonomous` flags.
- **DHCPv6** — stateful when you need DNS control, audit trails, reservations.
- **Dual-stack + Happy Eyeballs** — run both, race connections, measure v6/v4 ratio.
- **Transition** — NAT64/DNS64 for v6-only clients, 464XLAT on mobiles, tunnels for legacy links.

```bash
# Linux: static ULA + forwarding + RA guard basics
sudo ip -6 addr add fd00:lab:1::1/64 dev eth0
sudo sysctl -w net.ipv6.conf.all.forwarding=1
ip -6 route show
# FRR: advertise the prefix
# router ospf6 / interface eth0 area 0.0.0.0 ; redistribute connected
```

```
# dnsmasq DHCPv6 excerpt (stateful range + DNS)
# /etc/dnsmasq.d/ipv6.conf
enable-ra
dhcp-range=fd00:lab:1::100,fd00:lab:1::1ff,slaac,24h
dhcp-option=option6:dns-server,[fd00:lab:1::53]
```

## Week 4: QUIC and HTTP/3

QUIC moves transport into UDP userspace: 0–1 RTT crypto handshakes, independent streams (no TCP head-of-line blocking), connection migration across IP changes — the foundation of HTTP/3.

### QUIC vs TCP+TLS

| Feature | TCP + TLS 1.2 | QUIC + TLS 1.3 |
|---------|---------------|----------------|
| Handshake | 2–3 RTT | 0–1 RTT (resumption 0-RTT) |
| Loss in one stream | Blocks all (HOL) | Only that stream stalls |
| IP/port change | New connection | Migration, same CID |
| Middlebox ossification | TCP flags visible | Encrypted, versioned |

### HTTP/3 Consequences

QPACK (header compression for out-of-order streams), server push removed (use 103 Early Hints), UDP blocking on corporate firewalls becomes a deployment issue.

```python
# Compare HTTP/2 vs HTTP/3 handshake cost with curl (timing only)
# Requires curl with HTTP/3 support (nghttp3/ngtcp2)
import subprocess
for args in (["--http2", "https://example.com"],
             ["--http3-only", "https://example.com"]):
    r = subprocess.run(["curl", "-o", "/dev/null", "-s",
                        "-w", "%{time_connect} %{time_appconnect} %{time_total}\n",
                        *args], capture_output=True, text=True)
    print(" ".join(args[:1]), r.stdout.strip())
# Columns: TCP connect | TLS/app connect | total. Expect appconnect ~ 1 RTT lower on H3 resumption.
```

```bash
# Watch migration/blocking: QUIC is UDP/443 — confirm the path allows it
sudo tcpdump -i any 'udp port 443' -c 5
curl --http3-only -v https://example.com -o /dev/null 2>&I | head -20
```

## Week 5: 5G and the Road to 6G

5G splits radio and core into cloud-native functions: Service-Based Architecture, slicing, CU/DU disaggregation (O-RAN) and MEC put compute one hop from the antenna.

### Core Ideas

| Concept | What it is | Why it matters |
|---------|-----------|----------------|
| SBA core (AMF/SMF/UPF/NEF) | REST-based NFs | Sliceable, scalable control plane |
| Slicing (eMBB/URLLC/mMTC) | Virtual networks per SLA | One radio, many guarantees |
| CU/DU + O-RAN | Split baseband, open fronthaul | Multi-vendor, xApps/rApps |
| MEC | Edge UPF + apps | <10 ms latency, local breakout |
| 6G direction | THz, sensing+comms, AI-native air interface | Research now, standards ~2028+ |

### Slice Design Mini-Example


## Week 6: Data Center Fabrics — Clos and VXLAN

Modern DCs are Clos fabrics (leaf-spine, all ECMP) with EVPN-VXLAN overlays: any VM anywhere in a virtual L2, routed L3 underlay, BGP as the only protocol.

### Leaf-Spine + ECMP

```
   spine1   spine2
   /  \     /  \
leaf1 leaf2 leaf3 ... (servers hang off leafs only)
```

Oversubscription `leaf-uplinks : server-ports` (3:1 typical); ECMP hashes flows across all equal paths — elephant flows need flowlet/packet-spray help.

### EVPN-VXLAN Overlay

- **VXLAN** — L2-in-UDP (VNI = tenant), VTEPs on leafs.
- **EVPN (BGP)** — control plane advertises MAC+IP bindings; no flood-and-learn.
- **Anycast gateway** — same gateway IP/MAC on every leaf; first-hop stays local.

```bash
# FRR: eBGP underlay (unnumbered) + EVPN overlay skeleton
# /etc/frr/frr.conf excerpt
router bgp 65001
 neighbor fabric peer-group
 neighbor fabric remote-as external
 neighbor eth0 interface peer-group fabric
 !
 address-family ipv4 unicast
  redistribute connected
 address-family l2vpn evpn
  advertise-all-vni
```

```bash
# Linux VTEP sanity: VNI 10010 riding over 10.0.0.0/24 underlay
sudo ip link add vxlan10 type vxlan id 10010 dstport 4789 \
  local 10.0.1.1 nolearning
sudo ip link set vxlan10 up
bridge fdb show dev vxlan10 | head
```

## Week 7: WiFi 6 and WiFi 7

WiFi 6 (802.11ax) optimised *efficiency* (OFDMA, uplink MU-MIMO, BSS colouring, TWT); WiFi 7 (802.11be) adds *throughput + determinism* (320 MHz, 4096-QAM, Multi-Link Operation, multi-AP coordination).

### Generation Deltas

| Feature | WiFi 5 (ac) | WiFi 6 (ax) | WiFi 7 (be) |
|---------|-------------|-------------|-------------|
| MU access | DL MU-MIMO | + OFDMA, UL MU | + MLO, puncturing |
| Channels | 80/160 MHz | + 6 GHz (6E) | 320 MHz, 4096-QAM |
| Determinism | EDCA only | BSS colour, TWT | rTWT, multi-AP coord |
| Peak (1 AP) | ~3.5 Gbps | ~9.6 Gbps | ~46 Gbps (theory) |

### Planning Rules

1. 6 GHz for capacity/clean spectrum; keep 2.4 GHz for IoT reach.
2. Reuse with BSS colouring + transmit-power control, not just channels.
3. Separate latency-sensitive SSIDs; enable rTWT where supported.
4. Validate with surveys (RSSI, SNR, retries, airtime), not bars.

```bash
# Survey with Linux tools: scan, link quality, retries
sudo iw dev wlan0 scan | grep -E 'SSID|primary channel|signal' | head -30
iw dev wlan0 link
iw dev wlan0 station dump | grep -E 'Station|signal|tx .* retries' | head
```

## Week 8: Network Automation — NETCONF, YANG, Ansible

Clicking CLIs does not scale: model-driven automation (YANG models + NETCONF/RESTCONF) plus idempotent playbooks (Ansible/Nornir) make networks testable code.

### Stack

```
Intent (YAML inventory + variables)
  -> Template (Jinja2) -> Render per device
  -> Transport (NETCONF/YANG or RESTCONF or SSH) -> Commit + verify
  -> Test (pyATS/Batfish diff) -> Git history
```

### YANG/NETCONF in 30 Seconds

YANG models config *and* state; NETCONF edits `<running>` in transactions with commit/rollback; RESTCONF maps the same models to HTTP.

```xml
<!-- NETCONF edit-config: set hostname (RFC 6241 framing) -->
<rpc message-id="1" xmlns="urn:ietf:params:xml:ns:netconf:base:1.0">
  <edit-config>
    <target><running/></target>
    <config>
      <system xmlns="urn:ietf:params:xml:ns:yang:ietf-system">
        <hostname>leaf1</hostname>
      </system>
    </config>
  </edit-config>
</rpc>
```

```yaml
# Ansible: idempotent VLAN push + backup (ios/vyos/eos modules analogous)
- hosts: switches
  gather_facts: false
  tasks:
    - name: Ensure VLAN 10 exists
      community.network.vn_vlan:
        vlan_id: 10
        name: tenants-a
        state: present
    - name: Backup running config
      ansible.builtin.fetch:
        src: /config/running.cfg
        dest: backups/{{ inventory_hostname }}.cfg
        flat: true
```

## Week 9: Telemetry — SNMP to Streaming

SNMP polls every minutes; streaming telemetry pushes every seconds with structured paths — the difference between autopsy and intensive care.

### Generations

| Gen | Protocol | Model | Cadence |
|-----|----------|-------|---------|
| Poll | SNMPv2c/v3 | MIB/OID | 1–5 min |
| Flow | NetFlow/IPFIX/sFlow | 5-tuple aggregates | Per-flow expiry |
| Streaming | gNMI/gRPC, NETCONF notif. | YANG paths | 1–30 s subscriptions |
| In-band | INT (P4), eBPF events | Per-packet/hop | Line rate (sampled) |

### gNMI Subscribe Example

```python
# Streaming interface counters via gNMI (grpcio + pygnmi style pseudocode)
from pygnmi.client import gNMIclient

with gNMIclient(target=('leaf1', '6030'), username='admin',
                password='admin', insecure=True) as c:
    sub = c.subscribe(subscribe=[{
        'path': 'interfaces/interface[name=Ethernet1]/state/counters',
        'mode': 'sample', 'sample_interval': 10_000_000_000}])
    for msg in sub:
        print(msg)  # in_octets/in_errors deltas -> rate + alert
```

```bash
# eBPF instant view: retransmits + top talkers without a collector
sudo ss -tin | head -20
sudo tcpdump -i any -nn -c 1000 2>/dev/null | awk '{print $3}' | sort | uniq -c | sort -rn | head
```

## Week 10: IoT and Edge Networking

Millions of constrained devices speak MQTT/CoAP over lossy links; the edge (gateway/MEC) aggregates, filters and decides locally so the cloud sees insight, not noise.

### Protocol Picks

| Protocol | Transport | Pattern | Best for |
|----------|-----------|---------|----------|
| MQTT v5 | TCP (+TLS) | pub/sub, QoS 0–2 | Telemetry, commands |
| CoAP | UDP (+DTLS/OSCORE) | REST-like, observe | Constrained nodes |
| LwM2M | CoAP | Device mgmt | Firmware, provisioning |
| LoRaWAN | Sub-GHz | Aloha classes A–C | Battery km-range |

### Edge Pipeline

`sensor -> gateway (filter/dedupe) -> local rules (shutdown on threshold) -> batch uplink -> cloud twin`.

```python
# MQTT sensor publisher + edge threshold subscriber (paho-mqtt)
import json, paho.mqtt.client as mqtt

pub = mqtt.Client(); pub.connect("edge-broker.local", 1883, 60)
pub.publish("plant/zone1/temp", json.dumps({"c": 78.5, "id": "t-12"}), qos=1)

def on_msg(cli, ud, msg):
    c = json.loads(msg.payload)["c"]
    if c > 80.0:
        cli.publish("plant/zone1/cmd", json.dumps({"fan": "on"}), qos=1)

sub = mqtt.Client(); sub.on_message = on_msg
sub.connect("edge-broker.local"); sub.subscribe("plant/zone1/temp"); sub.loop_forever()
```

## Week 11: Zero Trust and SASE

Never trust, always verify: identity-aware proxying, device posture and per-session policy replace the "inside = safe" perimeter; SASE converges SSE security with SD-WAN delivery.

### Pillars

| Pillar | Control | Example |
|--------|---------|---------|
| Identity | MFA, short-lived certs (SPIFFE) | `user@`, `service-a` |
| Device | Posture, EDR signal | compliant + patched |
| Network | Microsegmentation, mTLS | workload-to-workload policy |
| Data | DLP, CASB | block PII upload |
| Access edge | ZTNA broker, SWG | no VPN hairpin |

### Policy as Code

```yaml
# ZTNA-style intent: only on-call engineers on compliant laptops reach prod DB
policies:
  - name: prod-db-access
    match:
      resource: db-prod-01:5432
      user_group: oncall
      device_posture: compliant
      mfa: true
    action: allow
    session_timeout_min: 60
    require_approval: true
  - name: default-deny
    match: {resource: "db-prod-01:5432"}
    action: deny
```

## Week 12: Quantum-Safe Networking

A cryptographically relevant quantum computer breaks RSA/ECC (Shor) and halves symmetric strength (Grover): migrate to NIST post-quantum KEMs/signatures now via hybrid handshakes and a crypto inventory.

### NIST PQC Winners (What to Deploy)

| Use | Algorithm | Notes |
|-----|-----------|-------|
| KEM | ML-KEM (Kyber) 512/768/1024 | Hybrid X25519+Kyber in TLS today |
| Signatures | ML-DSA (Dilithium), SLH-DSA (SPHINCS+), FN-DSA | Bigger keys/sigs — mind MTU/ handshake size |
| Symmetric | AES-256, SHA-384+ | Double strength vs Grover |

### Hybrid TLS Today

```bash
# OpenSSL 3.x with PQC provider: list KEMs, test hybrid group (names vary by build)
openssl list -kem-algorithms | grep -i -E 'kyber|ml-kem|x25519' | head
curl --curves X25519MLKEM768 -v https://pq-enabled.example.com -o /dev/null 2>&I | head -15
# Watch: larger ClientHello/KeyShare — confirm no middlebox fragmentation
sudo tcpdump -i any 'tcp port 443' -c 3 -v | grep -i -E 'length|fragment' | head
```

### Migration Playbook

1. **Inventory** — every RSA/ECC usage (certs, VPNs, firmware signing, code).
2. **Hybrid first** — classical + PQC so both eras verify.
3. **Size impact** — Dilithium certs ≈ kBs; test MTU, caches, embedded stacks.
4. **Crypto-agility** — negotiate algorithms; never hard-code one.

## Week 13: AI-Driven NOC — The Self-Driving Network

From dashboards to closed loops: detect (anomaly), decide (policy/ranker), act (automation from Week 8), verify (telemetry from Week 9) — with a human approval gate sized to blast radius.

### Closed Loop

```
stream telemetry -> features -> anomaly/rank -> action proposal
     -> blast-radius gate (auto | approve | freeze) -> Ansible/NETCONF
     -> verify KPI -> learn (label, retrain)
```

### Level Ladder

| Level | Name | Human role |
|-------|------|-----------|
| L1 | Assist (copilot summaries) | Decides everything |
| L2 | Supervised (proposed diffs) | Approves |
| L3 | Guardrailed (auto in blast radius) | On-call for pages |
| L4 | Autonomous (self-heal + report) | Audits |

```python
# Baseline + z-score anomaly on interface error rate (pandas)
import pandas as pd

s = pd.read_csv("if_errors.csv", parse_dates=["ts"]).set_index("ts")["err_rate"]

z = (s - roll.mean()) / roll.std().replace(0, 1e-9)
alerts = s[z > 4].dropna()
print(f"alerts: {len(alerts)}")
```

## Code Review Guide

### What to Look For

1. **Controller safety** — no blanket `output: flood`; table-miss goes to controller with rate limits.
2. **Idempotent automation** — playbooks converge; `--check --diff` clean on second run.
3. **Config hygiene** — secrets vaulted, versions pinned, diffs committed to Git.
4. **Observability** — every change emits telemetry; alerts reference runbooks.
5. **Blast radius** — canary + rollback plan for fabric-wide pushes.

```
ovs-ofctl add-flow s1 "actions=output:flood"
```

**Issues:** matches everything (no match fields, lowest implicit priority chaos); floods BPDUs/loops broadcast storms; no timeout/hardening; bypasses controller policy; invisible in version control. Fix with explicit match + priority + timeouts + controller-managed install.

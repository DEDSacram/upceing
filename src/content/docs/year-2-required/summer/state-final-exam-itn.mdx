## Exam Format

- **Parts:** (1) compulsory subjects block, (2) elective block (your chosen A + B subjects), (3) diploma thesis defence.
- **Form:** oral examination before a committee; you draw questions and present with reasoning, often with a whiteboard or short demo.
- **Passing:** demonstrate connected understanding, not memorised slides — explain trade-offs, work an example, justify a design choice.

## Preparation Plan

### 6-Week Plan

| Week | Focus | Output |
|------|-------|--------|
| 1 | Theory (automata, complexity) + queueing formulas | 1-page formula sheet |
| 2 | OS 1+2: sync, memory, scripting | Solved sync + paging exercises |
| 3 | Data: JPA/REST + warehousing + enterprise views | Mini trace: req → model → query |
| 4 | Elective A deep dive | Lab demo rehearsed (SPARK proof / simulator run) |
| 5 | Elective B deep dive | Lab demo rehearsed (GL scene / Mininet flows) |
| 6 | Mock exams: draw 3 questions, present aloud 15 min each | Gap list → patch revision |

### Method

1. One A4 "battle sheet" per subject: definitions, one diagram, one worked example.
2. Speak answers aloud with a timer; the committee tests reasoning under follow-ups.
3. Rehearse exactly one live demo per elective (proof log, simulation plot, shader, flow table).
4. Trade mock questions with a peer; grade each other on correctness + clarity.
5. Keep an error log: every failed mock answer becomes a flashcard reviewed within 48 hours.
6. Finish each subject with a 5-question self-quiz; below 4/5 means another pass.

### Battle-Sheet Template (copy per subject)

| Slot | Content |
|------|---------|
| Definitions | 5 core terms in your own words |
| Diagram | One architecture / pipeline / taxonomy figure (ASCII is fine) |
| Worked example | Numbers, code or trace you can reproduce on demand |
| Trade-offs | Two "X vs Y, when each wins" rows |
| Traps | Two classic mistakes + how you avoid them |

### Thesis Defence Prep

- [ ] 10-slide arc: problem → state of art → design → implementation → evaluation → conclusion
- [ ] One demo path rehearsed end-to-end (plus screenshots if hardware fails)
- [ ] Know your numbers: datasets, metrics, baselines, limitations
- [ ] Prepare answers for: "why this method?", "what would you do with 3 more months?", "threats to validity?"

## Sample Questions per Subject

### Theoretical Informatics (KAM/NNTEI)

1. Convert a regular expression to an NFA, then to a DFA — where can state explosion bite?
2. Show a grammar in CNF and build its derivation tree; why does CNF help parsing complexity?
3. Sketch a Turing machine deciding a language; argue why the halting problem is undecidable.
4. Prove a problem NP-complete by reduction (template: 3-SAT → your problem).

### Operating Systems 1 & 2 (KIT/NNOS1, KST/NNOS2)

1. Compare deadline vs FIFO/RR vs CFS scheduling with an example workload each.
2. Solve a producer-consumer with semaphores; then show the monitor version — what changed?
3. Walk a page-table lookup (4-level x86-64) including a TLB miss; explain demand paging.
4. Diagnose a deadlock from a lock-ordering diagram; propose prevention vs detection.
5. Write a PowerShell snippet for a registry + service audit; explain WMI's role.

### Programming Database Applications (KST/NNPDA)

1. Contrast JDBC vs JPA/Hibernate for one CRUD flow; where do N+1 queries come from?
2. Design a REST endpoint with validation + JWT auth; then sketch the SOAP equivalent.
3. Explain an Elasticsearch → Kibana → Logstash pipeline for application logs.

### Data Warehousing (KIT/NNDSK)

1. Model a sales mart as star vs snowflake; write a CUBE/ROLLUP query over it.
2. ETL vs ELT: when does each win? Sketch an ODI-style incremental load.

### Enterprise Architecture (KST/NAPIS)

1. Draw two ArchiMate views (business + application) of one process and link them.
2. Model an order process in BPMN; where do Solution Building Blocks plug in?

### Queueing Theory (KAM/NNTEF)

1. Classify a system in Kendall notation; compute mean queue for M/M/1 from λ, μ.
2. Compare M/M/n with infinite vs finite queue vs losses — which metric decides capacity?

### Elective: Safety (KST/NNBSW)

1. Build a fault → error → failure → hazard → accident chain for a real incident.
2. Read a SPARK postcondition + loop invariant; state what is proved.
3. Assign SIL/SSIL/DAL to a level-crossing controller and name five evidence artefacts.

### Elective: Simulation (KST/NNTMS)

1. Contrast event-driven vs agent-driven control on a traffic node example.
2. Explain addressed vs group vs broadcast messaging in an agent hierarchy.
3. CMB null messages vs Time Warp anti-messages; define GVT and fossil collection.

### Elective: 3D Graphics (KST/NNPG3)

1. Trace a vertex model → screen, naming every matrix and space.
2. Why Blinn-Phong in linear space? Explain acne vs peter-panning in shadow maps.
3. Write the linear-blend skinning equation; explain weight rules.

### Elective: Networks (KST/NNTPS)

1. Trace a packet through OpenFlow tables; when is the controller consulted?
2. Plan IPv6 addressing + RA-guard for a campus; why /64 per LAN?
3. Explain EVPN-VXLAN: what BGP advertises and why flooding disappears.
4. Contrast SNMP polling with gNMI streaming for outage detection time.
5. Walk a QUIC handshake vs TCP+TLS: round trips, migration, firewall impact.

### Year's Project & Diploma Thesis (KST/NNPRO, KST/NNDIP)

1. Present your requirements → architecture → implementation → testing trace in 5 minutes.
2. Which design decision was riskiest, and what evidence justified it?
3. How did you validate the result (tests, metrics, user feedback)? What are the limits?

### Grading Rubric (What Committees Reward)

| Criterion | Excellent | Fail signal |
|-----------|-----------|-------------|
| Correctness | Precise definitions, correct worked example | Guessing, hand-waving |
| Reasoning | Trade-offs + justification | One-sided answers |
| Connection | Links theory to your project/labs | Isolated facts |
| Presentation | Structured, timed, legible board work | Rambling, overtime |

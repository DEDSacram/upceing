## Week 1: JDBC Database Connections

JDBC is the foundational Java→SQL bridge: `DriverManager/DataSource → Connection → PreparedStatement → ResultSet`. See `upce/NNPDA/lab-01-jdbc/`.

### Key Concepts

- **DataSource + try-with-resources** - pooled connections, leak-free close. <span class="badge">Good</span> `HikariCP`; <span class="badge danger">Bad</span> string-concatenated SQL
- **PreparedStatement** - bind parameters, prevent injection, reuse plans
- **Transactions** - `setAutoCommit(false)`, commit/rollback, isolation levels

| Isolation | Prevents |
|-----------|----------|
| READ_COMMITTED | Dirty reads |
| REPEATABLE_READ | + non-repeatable reads |
| SERIALIZABLE | + phantoms (slowest) |

```java
// lab-01-jdbc: safe transfer with transaction
import javax.sql.DataSource;
import java.sql.*;

public class TransferDao {
    private final DataSource ds;
    public TransferDao(DataSource ds) { this.ds = ds; }

    public void transfer(long from, long to, long amount) throws SQLException {
        String sql = "UPDATE accounts SET balance = balance + ? WHERE id = ?";
        try (Connection c = ds.getConnection()) {
            c.setAutoCommit(false);
            try (PreparedStatement ps = c.prepareStatement(sql)) {
                ps.setLong(1, -amount); ps.setLong(2, from); ps.executeUpdate();
                ps.setLong(1, amount);  ps.setLong(2, to);   ps.executeUpdate();
                c.commit();
            } catch (SQLException e) { c.rollback(); throw e; }
        }
    }
}
```

## Week 2: REST Web Services

REST exposes resources over HTTP verbs with stateless JSON exchange. See `upce/NNPDA/lab-02-rest/`.

### Key Concepts

- **Constraints** - client-server, stateless, cacheable, uniform interface, layered
- **Resource naming** - nouns plural: `GET /students`, `GET /students/{id}`, `POST /students`, `PUT /students/{id}`, `DELETE /students/{id}`
- **Status codes** - `200/201/204/400/404/409/422`; versioning, pagination, ETag

```java
// lab-02-rest: Spring MVC controller
import org.springframework.http.*;
import org.springframework.web.bind.annotation.*;
import jakarta.validation.Valid;
import java.util.*;

@RestController
@RequestMapping("/api/v1/students")
public class StudentController {
    private final StudentService service;
    public StudentController(StudentService service) { this.service = service; }

    @GetMapping
    public List<StudentDto> list(@RequestParam(defaultValue = "0") int page,
                                 @RequestParam(defaultValue = "20") int size) {
        return service.list(page, size);
    }

    @PostMapping
    public ResponseEntity<StudentDto> create(@Valid @RequestBody StudentDto dto) {
        StudentDto saved = service.create(dto);
        return ResponseEntity.status(HttpStatus.CREATED).body(saved);
    }

    @GetMapping("/{id}")
    public StudentDto get(@PathVariable long id) { return service.get(id); }
}
```

## Week 3: SOAP Web Services

SOAP = contract-first XML messaging over HTTP with WSDL/XSD, WS-Security, and strict validation — still common in banking/government. See `upce/NNPDA/lab-03-soap/`.

### Key Concepts

- **WSDL + XSD** - operations, messages, faults; generate stubs (`wsimport`/`cxf-codegen`)
- **JAX-WS** - `@WebService/@WebMethod/@SOAPBinding`; SOAP fault ↔ Java exception
- **REST vs SOAP** - REST: lightweight JSON, caching; SOAP: contracts, ACID-ish WS-*, tooling

| Aspect | REST | SOAP |
|--------|------|------|
| Payload | JSON | XML envelope |
| Contract | OpenAPI (optional) | WSDL (mandatory) |
| State | Stateless | WS-* state possible |
| Errors | HTTP codes | SOAP faults |

```java
// lab-03-soap: JAX-WS endpoint
import jakarta.jws.*;

@WebService(serviceName = "StudentService")
public class StudentEndpoint {
    @WebMethod
    public Student findStudent(@WebParam(name = "id") long id) throws StudentFault {
        return StudentRepo.find(id)
            .orElseThrow(() -> new StudentFault("Unknown id: " + id));
    }
}
```

```xml
<!-- SOAP envelope sketch -->
<soap:Envelope xmlns:soap="http://schemas.xmlsoap.org/soap/envelope/">
  <soap:Body>
    <findStudent xmlns="http://nnpda.upce/">
      <id>42</id>
    </findStudent>
  </soap:Body>
</soap:Envelope>
```

## Week 4: Elasticsearch

Elasticsearch is a distributed JSON document store + search engine (Lucene). See `upce/NNPDA/lab-04-elasticsearch/`.

### Key Concepts

- **Index → type-less docs** - `_index/_id/_source`; mappings (text vs keyword, numeric, date)
- **CRUD API** - `PUT /students/_doc/1`, `GET`, `POST _update`, `DELETE`
- **Query DSL** - `match` (analyzed) vs `term` (exact), `bool` combinators, filters (cached)

```json
// lab-04-elasticsearch: mapping + query
PUT /students
{
  "mappings": {
    "properties": {
      "name":  { "type": "text" },
      "login": { "type": "keyword" },
      "year":  { "type": "integer" },
      "bio":   { "type": "text" }

  }
}

GET /students/_search
{
  "query": {
    "bool": {
      "must":   [{ "match": { "bio": "database systems" } }],
      "filter": [{ "term":  { "year": 2 } }]
    }
  }
}
```

## Week 6: Database Synchronization with Logstash

Logstash keeps SQL and Elasticsearch in sync: `jdbc` input → `filter` → `elasticsearch` output. See `upce/NNPDA/lab-06-logstash-sync/`.

### Pipeline

```
Relational DB --(jdbc input, tracking_column)--> filter (mutate/date)
   --> elasticsearch output (upsert by document_id) --> Kibana
```

- **Incremental sync** - `:sql_last_value` + `tracking_column => updated_at`
- **Idempotent writes** - `document_id => "%{id}"`, `action => "update"`, `doc_as_upsert`

```ruby
# lab-06-logstash-sync: logstash.conf
input {
  jdbc {
    jdbc_driver_library => "/drivers/postgresql.jar"
    jdbc_driver_class => "org.postgresql.Driver"
    jdbc_connection_string => "jdbc:postgresql://db:5432/nnpda"
    jdbc_user => "nnpda"
    schedule => "*/5 * * * *"
    statement => "SELECT id, name, year, updated_at FROM students WHERE updated_at > :sql_last_value"
    use_column_value => true
    tracking_column => "updated_at"
  }
}
filter {
  mutate { convert => { "year" => "integer" } }
}
output {
  elasticsearch {
    hosts => ["http://es:9200"]
    index => "students"
    document_id => "%{id}"
    action => "update"
    doc_as_upsert => true
  }
}
```

## Week 7: Hibernate

Hibernate implements ORM: entities ↔ tables via `Session`, HQL, lazy loading, caching. See `upce/NNPDA/lab-07-hibernate/`.

### Key Concepts

- **Session/SessionFactory** - unit of work; `get` (eager hit) vs `load` (proxy)
- **Mappings** - `@Entity`, `@Id @GeneratedValue`, `@ManyToOne/@OneToMany`, fetch types
- **N+1 problem** - lazy collections in loops; fix with `JOIN FETCH` / `@EntityGraph`

| Fetch | Behaviour |
|-------|-----------|
| LAZY | Proxy, loads on access (needs open session) |
| EAGER | Immediate join/select (careful: cartesian) |

```java
// lab-07-hibernate: entity + fetch join
import jakarta.persistence.*;
import java.util.*;

@Entity @Table(name = "students")
public class Student {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    private String name;
    @OneToMany(mappedBy = "student", fetch = FetchType.LAZY)
    private List<Enrollment> enrollments = new ArrayList<>();
    // getters/setters...
}

// HQL avoiding N+1
// "SELECT DISTINCT s FROM Student s LEFT JOIN FETCH s.enrollments WHERE s.year = :y"
```

## Week 8: Java Persistence API (JPA)

JPA is the standard API (`EntityManager`, JPQL, Criteria); Hibernate is one provider. See `upce/NNPDA/lab-08-jpa/`.

### Key Concepts

- **Entity lifecycle** - transient → managed → detached → removed; `persist/merge/remove`
- **Relationships + cascade** - `PERSIST/MERGE/REMOVE/ALL`, `orphanRemoval`, owning side (`mappedBy`)
- **JPQL/Criteria** - object queries, typed params, pagination; second-level cache

```java
// lab-08-jpa: repository with EntityManager
import jakarta.persistence.*;
import org.springframework.stereotype.Repository;
import org.springframework.transaction.annotation.Transactional;
import java.util.List;

@Repository
public class StudentRepository {
    @PersistenceContext private EntityManager em;

    @Transactional
    public Student save(Student s) { em.persist(s); return s; }

    public List<Student> byYear(int year, int page, int size) {
        return em.createQuery(
            "SELECT s FROM Student s LEFT JOIN FETCH s.enrollments WHERE s.year = :y", Student.class)
            .setParameter("y", year)
            .setFirstResult(page * size)
            .setMaxResults(size)
            .getResultList();
    }
}
```

## Week 9: Spring and Spring Boot

Spring Boot wires everything: IoC/DI, Spring Data repositories, validation, security. See `upce/NNPDA/lab-09-springboot/`.

### Key Concepts

- **DI/IoC** - constructor injection, `@Service/@Repository`, profiles
- **Spring Data JPA** - derived queries (`findByYearOrderByName`), `@Query`, specifications
- **Web + validation + security** - `@RestController`, Bean Validation, JWT filter chain

```java
// lab-09-springboot: repository + service
import org.springframework.data.jpa.repository.*;
import java.util.List;

public interface StudentRepo extends JpaRepository<Student, Long> {
    List<Student> findByYearOrderByNameAsc(int year);

    @Query("SELECT s FROM Student s WHERE lower(s.name) LIKE lower(concat('%', :q, '%'))")
    List<Student> search(String q);
}
```

```java
// Service with constructor injection + transaction
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

@Service
public class StudentService {
    private final StudentRepo repo;
    public StudentService(StudentRepo repo) { this.repo = repo; }

    @Transactional
    public Student create(Student s) { return repo.save(s); }
}
```

## Week 12: Docker Virtualization

Docker virtualizes the app environment: images (layered) vs containers (running), Compose for DB+app+ES. See `upce/NNPDA/lab-12-docker/`.

### Key Concepts

- **Dockerfile layering** - order by change frequency; multi-stage builds for small Java images
- **Compose** - services, volumes (data!), networks, healthchecks, env files
- **Ops** - tags, registries, `.dockerignore`, non-root user, read-only FS where possible

```dockerfile
# lab-12-docker: multi-stage Java build
FROM maven:3.9-eclipse-temurin-21 AS build
WORKDIR /app
COPY pom.xml .
RUN mvn -q -DskipTests dependency:go-offline
COPY src ./src
RUN mvn -q -DskipTests package

FROM eclipse-temurin:21-jre
RUN useradd -r app && mkdir /app && chown app /app
USER app
WORKDIR /app
COPY --from=build /app/target/*.jar app.jar
EXPOSE 8080
ENTRYPOINT ["java", "-jar", "app.jar"]
```

## Week 13: Oracle Spatial - MapBuilder and MapViewer

Oracle Spatial stores/query geometry (`SDO_GEOMETRY`); MapBuilder styles themes, MapViewer renders maps. See `upce/NNPDA/lab-13-oracle-spatial/`.

### Key Concepts

- **SDO_GEOMETRY** - `GTYPE` (point/line/polygon), `SRID` (e.g. 4326 WGS84), ordinates; spatial index (`MDSYS.SPATIAL_INDEX`)
- **Operators** - `SDO_WITHIN_DISTANCE`, `SDO_RELATE (ANYINTERACT)`, `SDO_NN` (nearest neighbour)
- **MapBuilder/MapViewer** - connection, theme (SQL + style), basemap, FOI/map tile requests

```sql
-- lab-13-oracle-spatial: nearest faculties within 5 km
SELECT f.name,
       SDO_GEOM.SDO_DISTANCE(f.geom, SDO_GEOMETRY(2001, 4326,
         SDO_POINT_TYPE(15.76, 50.03, NULL), NULL, NULL), 0.005) AS dist_m
FROM faculties f
WHERE SDO_WITHIN_DISTANCE(f.geom,
        SDO_GEOMETRY(2001, 4326, SDO_POINT_TYPE(15.76, 50.03, NULL), NULL, NULL),
        'distance=5000 unit=m') = 'TRUE'
ORDER BY dist_m;
```

## Code Review Guide

### What to Look For

#### 1. Data Access
- `PreparedStatement`/binds everywhere? No string-built SQL?
- Transactions scoped correctly? Lazy loading inside session or via DTO?

#### 2. API Design
- Nouns, plural, correct status codes? Validation + error envelope?
- Pagination on collections? No entity graph leaks (passwords, internals)?

#### 3. Search/Sync
- `text` vs `keyword` correct? Analyzer matches language? `document_id` upserts?

### Code Review Example

<div class="review-note">

<strong>🔍 Practice Review:</strong> Identify issues:

```java
@GetMapping("/students")
public List<Student> all(@RequestParam String name) throws Exception {
    Statement st = conn.createStatement();
    // BUG: SQL injection + leaking entities + missing pagination
    ResultSet rs = st.executeQuery("SELECT * FROM students WHERE name='" + name + "'");
    ...
}
```

**Issues:** injection (use `PreparedStatement`/JPA); returns entities (use DTOs); no pagination; connection never closed; throws raw `Exception` (map to 4xx/5xx).
